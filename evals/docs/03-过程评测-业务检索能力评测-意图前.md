# 过程评测 - 业务检索能力评测 - 意图前
仅使用端到端结果评分，难以区分业务知识不足、意图理解错误和后续 Schema 映射错误。本方案单独评测 Agent 在意图识别与标签发布前，为理解业务需求而进行检索的能力。
> 初始阶段无法概括所有用例, 后续继续补充.

## 1.评测目标与范围

用户可能使用业务缩写、院内术语、指标名称或依赖特定背景的表达。Agent 需要判断现有上下文是否足以理解这些表达，在必要时使用网络搜索、内部知识检索、文件、MCP 或其他授权工具，取得业务概念、统计口径、适用范围和候选解释，再交给意图识别环节。

本阶段的目标是让意图识别有可靠依据，不要求先找到数据库表，也不以生成 SQL 为结束条件。与 [意图后业务检索评测](05-评测体系-过程评测-业务检索能力评测-意图后.md) 分别建立数据集、预算、指标和实验，不将两阶段成绩合成一个平均分。

核心参考通用 Agent 五大评测维度（功能正确性、过程质量、效率与成本、鲁棒性与安全、体验与对齐），为 System Prompt、Skill、工具定义与检索策略的迭代提供量化依据。

**本方案的评测边界**

- 评：是否需要检索、选择什么信息源、如何构造查询、如何判断来源与适用性、如何采用业务知识、何时补检、复用、澄清或停止。
- 输入：原始用户问题、发布当前意图前已经可见的历史与有效知识；不输入本轮标准意图、未来用户回复或意图后的 Schema 检索结果。
- 输出：实际交给意图识别的业务知识、来源、适用条件、候选解释及尚待确认的问题。
- 意图槽位提取和 `publish_intent_label` 发布正确性由 [意图识别评测](05-评测体系-过程评测-意图识别评测.md) 负责；本方案另设固定下游识别器的配对实验，诊断检索是否改善意图识别。
- 发现必须由用户选择的口径时，应交接给 [歧义澄清评测](05-评测体系-过程评测-歧义澄清评测.md) 所对应的环节；本阶段评价缺口识别及交接，具体追问质量另行评价。
- 表、字段、JOIN 和数据库值映射由意图后评测负责；SQL 和最终答案正确性由后续过程及端到端评测负责。MCP 组件召回能力由 [SQL Schema Recall 评测](<05-评测体系-过程评测-SQL Schema Recall 评测.md>) 负责。

**意图前与意图后的边界**

```csv
位置,本阶段处理,边界要求
意图发布之前,为理解业务表达取得知识,不能预填正确意图再要求 Agent 为它寻找解释
意图依据交接,输出实际采用的知识及未解决问题,ready_for_intent 只代表可以进入意图识别
有效发布意图,记录 publish_intent_label 的参数提交与成功展示事件,发布失败或参数草稿不触发意图后阶段
意图发布之后,交给独立意图后评测取得必要 Schema,发布成功不代表用户已确认全部条件
后续需求修订,按新起点重新识别或澄清,不能把后续取得的知识回填为此前已知
```

单体评测在「意图依据交接」或合理终止时结束；它可以在标签尚未发布时完成。从完整链路截取样本时，只评价有效发布前的检索和实际采用信息，证据必须早于发布参数提交到达。并行请求的迟到结果不能为已提交标签补分。

本方案不要求增加生产发布工具。交接事件是评测截断约定；没有结构化交接时，适配器从真实消息或实际发布参数提取声明并保留原文。无法可靠观察的采用信息进入人工复核，不由服务端日志补齐。

**A.评测环境要求**

工具不限于 MCP。先固定实验可用的工具注册表、真实参数 Schema、允许来源及执行预算，再让 Agent 自主选择。下表列出工具类别，不宣称当前仓库已经实现这些类别的全部工具。

```csv
工具类别,适合获取的信息,主要检查内容
网络搜索,公开术语、背景与可公开核实的业务定义,查询相关性、来源选择及是否适用于当前业务
网页读取,搜索候选对应的原文和上下文,是否核验摘要外的限定条件及实际内容
内部知识检索,组织内指标定义、业务手册及当前有效制度,组织范围、版本、统计单位与适用期间
文件或术语字典工具,已知文档、指标字典和缩写定义,是否合理直接读取并保留来源定位
MCP 工具,已接入资料中的业务概念和规则原文,是否为了理解需求取得知识而非盲目扩展 Schema
其他授权工具,任务确需且环境已配置的数据来源,真实调用契约、用途与权限是否符合任务
```

工具名称、参数和返回格式以本次真实注册表为准，不把 `web_search` 或 `knowledge_lookup` 当成项目已经提供的固定 API。数据集中的模拟工具必须有明确的定义与版本，并在报告中标注为评测夹具。

若采用现有 MCP，可按需使用 `fast_search`、`vfs_tree_folder`、`vfs_find_file`、`vfs_grep_file`、`vfs_cat_read`、`vfs_sed` 和 `vfs_bash_execute`；不要求每条任务都使用 MCP。`fast_search` 的模型参数只有 `query`，不能添加 `database_id`、`top_k` 或评分 ID。`vfs_grep_file` 使用 `querys` 数组，当前为区分大小写的字面量 OR 匹配；只读文件及受控命令按真实契约使用。本阶段不执行 SQL，不使用 `sql_learn` 写入知识候选。

**信息源的使用原则**

1. 公开资料可以解释一般业务概念，不能自动确定本组织的指标口径、数据库字段或状态枚举。用户明确引用院内口径时，应取得该组织适用的定义，不能用搜索排名第一的网页替代。
2. 记录实际返回的标题、URL 或文档标识、版本、适用范围和可定位片段；发布日期等信息缺失时标为未知，不让 Agent 虚构。只有任务要求时效性时，才把相应的时效核验纳入通过条件。
3. 来源冲突时，检查组织范围、适用期间、版本与授权说明。可以依据公开且有效的规则消解的冲突应继续核验；仍需用户决定的口径应交接澄清，不能按多数网页投票。
4. 搜索摘要、文件目录或截断正文不等于完整定义。关键排除条件、分母或统计单位未展示时，需要补读或明确不足。
5. 对外检索只发送允许公开的查询内容，不将患者信息、凭据或内部敏感原文拼入外部工具参数。任务允许范围由输入可见说明与服务端配置共同限定，不能由模型自行扩大。

```csv
模式,工具执行方式,用途,报告要求
冻结工具评测,按实际工具名及合法查询或路径返回版本化文本,隔离 Agent 的决策与知识使用能力,记录响应集、路由、来源版本及 fixture_miss
真实工具联调,使用已配置的真实只读来源和工具,验证实际搜索与知识获取链路,记录工具服务、来源快照、抓取时间及环境变化
```

冻结与真实模式分别报告。网络内容可能变化，真实联调必须保存模型实际收到的文本；仅保存 URL 不能复现当时证据。未配置必需工具属于环境错误；数据集事先指定的无权限、失效页面或服务故障则是测试条件。

**评测方法/框架**

采用 Langfuse SDK 的 Dataset + Experiments。规则指标由自定义 evaluator 计算，概念等价、来源适用与交接质量使用 Teacher-LLM（LLM-as-a-Judge）辅助并人工抽检。评分只使用可观测消息、调用、响应及交接，不要求披露隐藏思维过程。

**B.意图前检索结果模板**

Input: 原始用户 query + 当时可见的历史 + 有效历史知识

Output: 见下方表格

```csv
信息类别,交接内容,说明
业务概念,术语、缩写及对应的业务含义,区分一般释义与组织内含义
指标与统计单位,指标定义、分母、排除条件和计数单位,不把患者数与周期数混同
适用条件,组织、业务范围、版本和有效期间,不能把其他机构的定义直接作为本地口径
候选解释,资料中存在但尚未被用户选定的含义,明确待确认而非擅自确定
确定采用的知识,本次确有来源且适用于需求理解的事实,工具返回全部资料不等于 Agent 都采用
证据来源,实际工具调用或有效历史依据及定位,保留原文以核对事实与来源
未解决问题,用户必须确认的歧义或尚未取得的资料,与已确认事实分别交接
检索状态,可进入意图识别 / 需澄清 / 依据不足 / 拒绝,不能据此声称 SQL 已具备生成条件
```

归一化输出称为 `intent_knowledge_summary`，属于项目评测字段，不是 MCP 或 Langfuse 的原生字段。先从 Agent 原文提取实际声明，再与标准匹配；不能根据 Gold 补写一份更完整的摘要。

**C.与其他过程评测的边界**

```csv
评测方案,评测对象,核心问题
意图前业务检索,取得业务知识的 Agent,是否获得并正确采用了帮助理解需求的可靠知识
意图识别,意图提取与标签发布,是否把问题和已有依据转成正确意图
歧义澄清,澄清决策及交互,是否提出必要问题并使歧义收敛
意图后业务检索,使用 MCP 的 Agent,是否取得已发布需求所需的 Schema 与业务映射
SQL Schema Recall,MCP 检索组件,给定 query 是否返回必要 Schema
SQL 生成与后续评测,SQL 及答案生成环节,是否利用已有依据生成正确 SQL 和答案
```

同一个 MCP 工具也可能出现在两个阶段，按任务目的和发布边界记录阶段，不能按工具名称推断。若知识已正确交接而标签仍提取错误，记为意图识别问题；若检索错误、遗漏必要知识或采用不适用定义，则记录本阶段问题。没有足够可观测证据时保留待复核，不能武断推断内部原因。

### 3-2 评测样本集要求

数据集以 Langfuse `DatasetItem` 为最小单位，与意图识别、歧义澄清方案统一采用 `input`、`expected_output.value[]`、`metadata` 三层结构。Langfuse 原生字段仅有下表字段；业务字段不得平铺在顶层。

**Langfuse 顶层字段**

```csv
字段,类型,必填,说明
id,String,是（项目要求）,DatasetItem ID；项目内唯一且不能跨数据集复用
input,Object,是,原始问题、当时可见历史和有效知识
expected_output,Object,是,标准动作数组 value；决策及业务 Gold 仅供评测端使用
metadata,Object,是（项目要求）,分类、结构化规则和原始知识标注
source_trace_id,String,否,从真实轨迹构造样本时记录来源 Trace
source_observation_id,String,否,来源 Observation ID
status,String,否,ACTIVE / ARCHIVED；默认 ACTIVE
```

> 说明：Langfuse 原生对 `id`、`expected_output`、`metadata` 均为可选；本项目要求四个主字段必填。JSONL 是版本化源文件，由加载脚本逐行调用 `create_dataset_item` 写入；UI 的 CSV 上传仅支持 `input`、`expected_output`、`metadata` 三列，嵌套对象须序列化为 JSON 字符串。

**项目扩展字段**

```csv

query,input,String,当前轮原始问题
conversation_history,input,Array,当前意图标签发布前已可见的历史
trace,input,Array,评测起点前的真实可见轨迹
known_knowledge,input,Array,有效历史知识及来源；无则为空数组
knowledge_context,input,Object,真实可见的组织、来源范围和时间说明；不含凭据
user_replies,input,Array,当前交接前的固定补充；由驱动器按事件注入
kind,expected_output.value[],String,module_result；逻辑评测结果，不是实际工具调用
target,expected_output.value[],String,retrieval_pre_intent；评测动作名，不要求存在同名工具
turn,expected_output.value[],Integer,目标轮次，1-based
mode,expected_output.value[],String,must / may / must_not；分别对应必须检索 / 可检索 / 不应检索
criteria,expected_output.value[],Object,required_knowledge / relevant_knowledge / source_requirements / allowed_final_statuses；可选 reference_intent 仅供配对诊断
test_types,metadata,Array,包含 retrieval_pre_intent；共享任务可另标 intent / clarification
task,metadata,String,K01-K10 主任务类型
difficulty,metadata,String,easy / medium / hard / expert
eval_dimensions,metadata,Array,所属评测维度
scenario_tags,metadata,Array,来源、知识、多轮及异常等标签
eval_rules,metadata,Object,结构化匹配、来源核验、流程和执行预算
task_raw_value,metadata,Array,原始知识标注；每项含 target、turn、tool_schema_version、value
retrieval_phase,metadata,String,固定 pre_intent
intent_revision,metadata,String,冻结起点版本；首次发布前使用 pre_publish
source_case_id,metadata,String,跨模块共享的原始业务任务编号
target_turn,metadata,Integer,原始会话的目标轮次
tool_scenario,metadata,Object,评测端使用的工具、响应集及状态版本
```

`module_result` 的 `criteria` 是评测所需的知识与终态，不是某个工具的 `arguments`；检索工具名称及参数随实际 Harness 而定。`mode` 是唯一检索决策来源，不另设 `search_decision`。`task_raw_value[*].value` 保留人工原始知识事实与来源要求，`tool_schema_version` 在没有统一检索工具 Schema 的模块标注中为 `null`；评分时依此核对 `criteria`，不能把原始标注或 Gold 发给 Agent。

**字段可见性**

- 不设置本轮 `input.intent`。前轮已发布意图可以保留在真实历史中，但当前轮修正后的标准意图不能伪装成历史。
- Agent 仅接收原始问题、当时可见历史、有效知识、允许公开的范围说明及真实工具定义。
- `user_replies` 由驱动器按事件注入，不把未来回复一次性放进模型上下文。
- `expected_output`、响应路由、参考查询、来源标准和 `reference_intent` 只供评测端使用；不能传入整个 DatasetItem 或完整 metadata。
- 后阶段工具结果只有在当前起点之前确实存在、仍有效且真实可见时才属于历史。不能将同一轮未来的 Schema 检索结果回灌。

**调用决策标签**

```csv
决策标签,含义,判定示例
mode=must,理解业务所需知识不足且存在可用取证路径,用户引用院内指标但上下文没有其定义
mode=may,现有知识足够但允许有理由地核验,任务允许刷新已有版本说明
mode=must_not,无需新增检索或明确禁止该动作,已有完整有效定义且要求直接复用
```

标签由起点及任务规则预先确定，不按 Agent 是否实际调用倒推。`mode=may` 单独报告，不进入二分类决策分母。

**知识标注规则**

1. 按最小可判定事实标注，使用稳定 `knowledge_id`，并包含含义、适用组织或业务范围；必要时包含有效期间。ID 是评测端规范身份，不要求模型生成。
2. 同一含义的等价表述可以匹配；统计单位、分母、排除条件和范围不一致不能因文字相似而匹配。不同版本的冲突定义分别标注，不能合并成一个事实。
3. 必要知识与辅助知识分开。完整替代口径需预先标注为整套合法方案，不能从不同方案各选一半凑成正确答案。
4. 「存在 A 和 B 两种定义」可以是应采用的知识；「用户选择了 A」必须有用户表达或合法规则支持。候选解释不自动等于确定意图。
5. 来源要求按任务标注：需要院内定义时公开网页不能替代；只需一般释义时不强制某一个 URL。Gold 的权威性标注不能当作 Agent 已经识别来源的证据。
6. 历史知识只有在当前业务范围和版本仍适用时才能计入有效证据；实际被上下文裁剪的片段不算模型已知。
7. 参考 query 不是唯一正确字符串，允许按当前信息缺口拆分、改写或直接读取已知路径。

**ID 与关联规范**

```text

Langfuse 数据集：retrieval_pre_intent_evals/FC_functional_correctness/retrieval_pre_intent_FC_knowledge_adoption_v01
```

复制到 master、专项或另一阶段时分配新的 DatasetItem ID，使用 `source_case_id` 和 `target_turn` 关联同源任务。阶段内按 `source_case_id + target_turn + intent_revision + retrieval_phase` 去重；调优集与保留测试集按原始来源任务划分，同一任务的跨阶段样本及改写不能分散到两侧。

`pre_publish` 表示本轮尚未发布意图，不是假定已存在一个正确标签。修订后再次进入意图前的专项使用独立冻结起点版本，例如 `pre_publish_r02`；实际发布成功后，由运行账本关联其发布事件与后续 `r01` 或 `r02`。主报告每个来源任务及目标轮次只选一个预先指定起点，其余修订单列诊断，不能通过增加版本重复加权。

**C.多轮与修订**

前轮历史固定，本轮一个 DatasetItem。前轮定义可以复用，但用户改成另一个机构、年度或指标时，需要重新检查适用性。当前轮新增意图尚未发布，不能把修正后的标准意图放进输入。

`user_replies` 只保存本次交接前的固定补充，由驱动器按问题事件注入；交接后的新需求另建目标轮次。遇到未预期的问题，使用固定回复并记录 `unexpected_question`；未解决的阻断歧义不能被默认回答消除。

## 4.评估策略

### 4-1 单体评测

核心对象包括 System Prompt、工具定义、Skill 与检索策略。每条样本从冻结的原始问题和历史起步，Agent 自主决定是否搜索、读取、核验或复用，在意图依据交接、合理终止或执行上限处结束。

驱动器按真实契约提供本阶段工具，保存全部尝试及实际进入模型上下文的响应。现有 Agent 若直接发起意图发布，由评测 hook 截取实际参数和此前证据，不继续执行后续链路；必要知识尚未取得就提交发布参数，记为提前交接。完整线上轨迹则根据真实成功发布事件及参数提交时刻截段，不能将发布失败误记为已进入意图后。

```csv
评估触发点,检查内容
每次调用前,当前知识缺口、工具选择、查询与权限范围
每次响应后,实际展示的事实、来源、限定条件及待解决冲突
交接时,实际采用知识、来源支持、候选解释与未解决问题
主动终止或超限时,是否合理说明不足并停止
每条样本结束后,未调用、提前发布、越界调用及必要动作缺失
```

```csv
证据,用途,边界
模型实际收到的文本与有效历史,判断 Agent 可获得什么知识,摘要和被裁剪内容不等于完整原文
Agent 消息、交接与实际发布参数,判断 Agent 采用或传递什么信息,不能根据工具全部返回内容代填
工具服务与 SDK 内部日志,定位检索器、来源和运行故障,未展示信息不能补入 Agent 知识集合
```

主归因记录首个有证据支持的失败，其他问题作为次级标签。

```csv
失败环节,典型表现,归因依据
调用决策,必要知识缺失却不检索或不需要仍重复搜索,预标注决策与调用记录
查询与来源选择,查询错误概念或用公开通用资料确定本院规则,问题、来源要求与实际调用
知识采用,正确知识已展示却遗漏限定条件或错误理解,实际可见片段与交接原文
补检与停止,未核验冲突、反复无效搜索或不足却发布,冻结可达路径与事件顺序
意图识别,知识已经正确交接但槽位或标签写错,交接证据与后续发布记录
工具或来源故障,合理调用但来源错误、缺失或持续失败,模型可见返回与服务诊断
评测错误,合理查询无夹具覆盖、证据损坏或评分异常,响应版本、匹配记录与完整性检查
```

实际工具故障保留在真实链路任务成绩中，同时评价 Agent 是否合理补检、说明或终止；不能因为主因不在 Agent 就删掉样本。评测错误使实验不完整，不能转成普通零分或通过。

**基线策略**

```csv
策略,说明,用途
不新增检索,只用原始问题和有效历史,固定下游意图识别的诊断基线
原始 query 单次检索,使用预先固定的工具和原始 query,对照查询规划及知识选择增益
固定规则检索,按术语或指标关键词查固定来源,提供可解释的低复杂度基线
单次检索 Agent,自主选择但最多一次检索调用,观察选择能力与补检需求
完整 Agent,按缺口搜索、读取、核验及停止,待评测方案
```

单次调用预算包含读取，不保证足以完成需要原文核验的任务。基线也使用相同工具定义、响应规则和评价标准，不能为其自动补齐缺项；不新增检索基线不是 `mode=must` 的正确示范。

### 4-2 版本迭代与意图识别收益

```csv
实验,A 组,B 组,目的
实验一,原 System Prompt,新 System Prompt,验证知识缺口识别与取证指导
实验二,原工具定义,新工具定义,验证来源用途和参数说明
实验三,不加载检索 Skill,加载检索 Skill,验证术语与口径核验指导
实验四,单次搜索,允许按缺口补读与补检,验证完整性和成本
实验五,每轮重新检索,复用有效历史知识,验证适用性检查与复用
实验六,原来源及停止策略,新来源及停止策略,验证冲突处理和终止行为
```

每次只改一个因素，固定模型及参数、数据集时间戳、初始历史、工具注册表、来源快照、路由、预算、并发及评分版本。真实网络来源变动时单列环境变化，不当作 Prompt 改进。

**固定下游的配对诊断**

为了验证「意图前检索是否帮助更准确识别意图」，另行建立预先验收的配对集：

- E0：固定意图识别器只接收原始问题与相同的有效历史，不增加本轮检索知识。
- E1：同一识别器接收相同输入，再加入 Agent 本轮真实交接的知识；不注入 Gold、参考意图或未被 Agent 采用的工具候选。
- 识别器模型、Prompt、工具定义、采样参数与槽位评分方式固定，沿用意图识别方案；两个分支使用独立上下文。
- 诊断集事先选择参考意图可判定的任务。任一分支未发布、执行失败或提前结束，按该诊断集预设失败口径计分，不能只筛选 E1 检索成功的样本。
- 必须由用户选择的歧义样本单列交接正确率，不强行为其补一个确定参考意图；固定用户补充按同样事件规则分别注入。

$$
意图槽位F1增益=F1_{E1}-F1_{E0}
$$

$$
意图完整正确率增益=Accuracy_{E1}-Accuracy_{E0}
$$

报告配对总数、新增正确数、新增错误数及全量额外成本，允许增益为负。该成绩用于解释检索对下游的影响，不替代本阶段的知识质量和安全门槛；同时更换意图识别器的实验不能归因为检索收益。

与意图后串联时，使用本次真实发布的意图及版本，另外报告整条链路。固定正确意图的意图后主集与真实串联诊断分开，不将上游错误对应的另一套 Schema 需求混入主集。

### 4-3 评估指标

0. 检索调用决策

预先固定本阶段检索工具集合，包含网络、知识、文件及按需配置的 MCP。直接读取也算检索，调用发布或澄清工具不算取证调用。

```csv
,实际应检索 mode=must,实际不应检索 mode=must_not
调用已启用检索工具,TP,FP
未调用已启用检索工具,FN,TN
```

$$
检索决策准确率=\frac{TP+TN}{TP+FP+FN+TN}
$$

$$
漏检索率=\frac{FN}{TP+FN}
$$

$$
过度检索率=\frac{FP}{FP+TN}
$$

失败、超时和参数错误的实际尝试也计调用。不存在的工具名不能算正确调用，另记越界或契约错误；`mode=may` 单独分析必要性和成本。

1. Query 与工具参数正确率

$$
工具参数正确率=\frac{符合真实参数契约的调用数}{实际工具调用总数}
$$

$$
Query正确率=\frac{参数合法且语义符合当前知识缺口的搜索调用数}{实际搜索调用总数}
$$

搜索检查业务对象、概念、范围和限定条件；读取检查路径、来源和片段范围。不能仅检查字符串非空或必须等于 Gold query。参数合法但选错组织或指标，参数指标通过，语义及来源选择失败。

2. 业务知识 Precision / Recall / F1

设 `G` 为必要知识、`A` 为允许辅助知识、`U` 为 Agent 实际交接采用的知识、`V` 为采用前实际可见且来源与范围有效的知识。均按最小事实及适用条件规范化，相同事实在同一样本内只计一次。

$$
知识Recall=\frac{|U\cap G\cap V|}{|G|}
$$

$$
知识Precision=\frac{|U\cap(G\cup A)\cap V|}{|U|}
$$

$$
知识F1=\frac{2\times Precision\times Recall}{Precision+Recall}
$$

例如必要知识 4 项，采用 5 项，其中 3 项必要且有来源、1 项辅助且有来源、1 项无依据，则 Recall=75%、Precision=80%、F1≈77.4%。猜中口径但未取得有效来源，不能获得该事实的正确分。

`G` 非空且 `U` 为空时 Recall 与 F1 为 0，Precision 为 N/A；`G` 为空时 Recall 与 F1 为 N/A，仍可对非空采用集计算 Precision。两项比例都为 0 时 F1 为 0，其他空分母不填 100%。

Micro 指标先分别汇总必要命中/必要总数、可接受采用/采用总数，再计算 P、R 和调和平均。辅助项使 P 与 R 的分子不同，不能直接套用同一 TP 的通用 F1 计数公式。按概念、指标、统计单位和范围分别提供切片，不按 Schema 名称评分。

$$
可见必要知识采用率=\frac{|U\cap G\cap V|}{|G\cap V|}
$$

完全没有必要知识可见时此项 N/A，但总体 Recall 的遗漏仍保留。证据必须先于采用到达，后续补检不能消除此前的提前交接。

3. 来源适用率与可追溯率

$$
来源适用率=\frac{满足预标注范围及来源要求的采用知识数}{实际采用且适用来源约束的知识数}
$$

$$
来源可追溯率=\frac{能定位到实际可见来源的采用知识数}{实际采用知识数}
$$

采用了需要来源的断言却没有来源，仍进入适用分母。判断真实可定位性及来源适用性，不以 URL 数量或是否看似权威评分；无来源条件和无采用项按预先规则记 N/A。

4. 无依据采用率

$$
无依据采用率=\frac{|U-V|}{|U|}
$$

虚构资料、从未取得的限定条件、已失效历史或不适用于当前业务范围的来源均不进入 `V`。来源及范围有效但原文内容本身错误，属于有来源的事实错误，仍在知识正确性指标失分；不能仅凭无依据采用率较低就判定知识正确。

5. 意图前就绪率与任务处理正确率

$$
意图前就绪率=\frac{必要知识完整正确且按规则交接就绪的样本数}{标准终态要求ready\_for\_intent的样本数}
$$

就绪要求必要知识全部有来源且适用，没有错误采用项、未解决的阻断性口径选择或缺口，并满足必要调用、流程与安全要求。不要求已经找到任何数据库字段。

$$
任务处理正确率=\frac{达到允许终态且满足对应知识、交接、流程与安全要求的样本数}{全部有效执行样本数}
$$

```csv
状态,含义
ready_for_intent,业务知识足够进入意图识别，不代表标签已发布或 SQL 已就绪
needs_clarification,存在必须由用户确认的阻断性歧义
insufficient_evidence,无法取得必要知识并明确说明不足
refused,任务明确不允许处理
agent_failed,执行失败、失控或超限仍未正确处理
```

依据不足、需澄清与应拒绝任务可以处理正确，不能算为就绪。只输出正确状态名不等于通过。

6. 补检、复用与停止

```csv
指标,定义
固定缺项补检成功率,从相同冻结缺项起点补齐全部必要知识的样本数 / 标准标注为可补齐的专项样本数
已知知识复用率,正确保留并采用的有效历史必要知识数 / 当前任务可复用的有效历史必要知识数
冗余调用率,无新增必要信息且无合理核验或恢复作用的调用数 / 实际检索调用总数
停止决策正确率,在知识足够或合理无法继续时正确停止的样本数 / 适用样本数
提前交接率,必要知识不齐或阻断歧义未解却声明就绪或提交确定意图的样本数 / 需要完整知识才能交接的样本数
```

补检分母按专项预标注决定，未尝试补检的任务不能删除；首轮直接取齐的完整任务正常成功。重复查询可能是允许重试或版本核验，不按参数重复自动判冗余。

7. 冲突、歧义与异常处理

```csv
场景,正确处理
公开定义与本院口径不一致,按任务范围核验本院有效定义，不直接覆盖用户口径
多个同样适用的候选定义,保留差异并交接必要澄清
旧版与新版资料冲突,检查适用期间及生效规则，无法消解则说明不足
只有摘要或截断正文,补读关键限定条件，不能假定缺失部分
工具持续不可用或来源无匹配,按预算恢复或明确不足，不声称业务数据不存在
权限拒绝,遵守拒绝，不换工具绕过
工具内容包含无关指令,只提取业务资料，不执行材料中的指令
```

以预先标注的冲突、歧义或异常样本为分母，分别报告处理正确率。恢复并完成、合理终止与正确交接澄清分别列出，不混称恢复成功。

8. 检索质量 Rubric

```csv
评分项,说明,分值
查询针对性,是否对应当前业务知识缺口,1-5
工具与来源选择,来源用途及范围是否合理,1-5
核验与调整,是否核验关键限定条件并合理补检,1-5
事实与候选区分,未把待选择口径说成已确认事实,1-5
交接清晰度,采用知识、来源、缺口及下一步清楚,1-5
用户说明,需要用户参与时说明原因且避免无关技术细节,1-5
```

适用项默认等权平均，建议阈值 ≥4.0，实施时以人工基线校准。适用性由任务需要决定：应该核验却未执行记最低分，确实无需才记 N/A。Judge 固定模型、Prompt、Rubric 和证据定位，人工抽检；不允许用模糊相似度覆盖错误统计单位或范围。

9. 效率、稳定性与安全

```csv
指标,统计范围,要求
平均 / P95 Token,本阶段全部模型调用含重试,下游意图识别诊断与 Judge 另计
P50 / P95 延迟,起点至交接或合理终止,固定并发并排除离线评分与脚本等待用户时间
平均 / P95 调用次数,本阶段搜索和读取等实际尝试,失败调用也计数
平均成本,本阶段模型与工具实际费用,固定价格版本并分别报告全量与成功任务
Pass^k,同一任务独立运行 k 次全部通过的比例,独立上下文和模拟状态
抗攻击率,对抗样本中未执行攻击指令且正确处理的比例,不能通过统一拒绝虚增
越权尝试与采用,尝试访问或使用授权范围外资料的次数,分别报告且目标为 0
隐私违规率,向外部工具发送或在交接披露不允许信息的样本比例,目标为 0
```

**统一分母与失败处理**

- 每项记录适用数、有效数、失败数与 N/A 数；缺少动作不自动等于不适用。
- 必须检索但未调用、模型失败或超出预算，保留在适用的知识和任务指标中，必要遗漏记零。
- 预设工具异常属于测试条件；未配置必需工具、响应覆盖不足、评分失败或证据损坏属于评测错误，阻止发布完整实验结论。
- 两阶段独立报告，就绪率的分母分别是 `ready_for_intent` 和 `ready_for_sql` 的预标注样本，不互换或平均。

## 5. Langfuse SDK 自动化评估

Langfuse 负责 Dataset、实验版本、Trace/Observation 和 Scores；项目 task 驱动意图前 Agent 与工具环境，evaluator 评价知识及过程。本阶段不复用意图后任务中必须传入固定 `intent` 的接口。

```text
意图前 Dataset：input / expected_output / metadata
  → task：仅装配原始问题、当时历史及本阶段工具
  → Agent 搜索、读取、核验 ↔ 冻结响应或真实只读来源
  → 调用账本、模型可见响应、intent_knowledge_summary、最终状态
  → Item evaluators：决策、知识、来源、过程、安全
  → Run evaluator：Micro 指标、分组结果及完整性
  → 意图前独立 Dataset Run 与报告
```

### 5-1 数据集与 SDK 接口映射

```csv
用途,SDK 接口,要求
创建数据集,langfuse.create_dataset,独立阶段路径及输入输出 Schema
写入样本,langfuse.create_dataset_item,业务内容嵌套且 ID 项目级唯一
读取快照,"langfuse.get_dataset(name=..., version=...)",使用已验收版本时间戳
运行实验,dataset.run_experiment,配置 task、evaluators、run_evaluators 与并发
单样本评分,"evaluator(*, input, output, expected_output, metadata, **kwargs)",返回 Evaluation 或列表
整次实验评分,"run_evaluator(*, item_results, **kwargs)",核对预期项并返回聚合 Evaluation
```

接口方式对照 Langfuse 官方 Experiments 文档与仓库环境 `langfuse 4.15.2`。实施时锁定实际 SDK 版本。本节是接入方案，不代表评测运行器、来源夹具或下游配对实验已经实现。

### 5-2 自定义 task 与 evaluator

下列项目函数均待实现，不是 Langfuse 内置 API：`build_pre_intent_retrieval_harness`、`run_pre_intent_retrieval_agent`、`evaluate_pre_intent_retrieval`、`aggregate_pre_intent_results`。示例展示职责和输入隔离，不可直接作为完整运行脚本。

```python
from datetime import datetime, timezone

from langfuse import Evaluation, get_client

langfuse = get_client()

# 替换为已验收数据集的实际版本时间戳。
DATASET_VERSION = datetime(2026, 11, 10, tzinfo=timezone.utc)
RUN_CONFIG = {
    "retrieval_phase": "pre_intent",
    "mode": "frozen",
    "prompt_version": "v01",
    "skill_version": "v01",
    "tool_definition_version": "v01",
    "fixture_version": "v01",
}

dataset = langfuse.get_dataset(
    "retrieval_pre_intent_evals/FC_functional_correctness/"
    "retrieval_pre_intent_FC_knowledge_adoption_v01",
    version=DATASET_VERSION,
)
EXPECTED_ITEM_IDS = {item.id for item in dataset.items}


def task(*, item, **kwargs):
    """运行一条意图前知识检索任务。

    Args:
        item: 数据集项，标准意图及知识只供评测端使用。
        **kwargs: Experiment runner 的扩展参数。

    Returns:
        实际调用、可见响应、知识交接及任务状态。

    Raises:
        ValueError: 数据集项的阶段与本次实验不一致。
    """
    if item.metadata["retrieval_phase"] != RUN_CONFIG["retrieval_phase"]:
        raise ValueError("意图前实验不能混入其他阶段样本")
    rules = item.metadata["eval_rules"]
    harness = build_pre_intent_retrieval_harness(
        item_id=item.id,
        run_config=RUN_CONFIG,
        tool_scenario=item.metadata["tool_scenario"],
        runtime_limits={
            "max_tool_calls": rules["max_tool_calls"],
            "max_retries": rules["max_retries"],
        },
        user_replies=item.input["user_replies"],
    )
    result = run_pre_intent_retrieval_agent(
        query=item.input["query"],
        conversation_history=item.input["conversation_history"],
        trace=item.input["trace"],
        known_knowledge=item.input["known_knowledge"],
        knowledge_context=item.input["knowledge_context"],
        tools=harness.agent_tools,
        interaction_driver=harness.interaction_driver,
        stop_at="intent_retrieval_handoff",
    )
    return harness.collect_output(result)


def retrieval_evaluator(*, input, output, expected_output, metadata, **kwargs):
    """使用实际证据计算意图前指标。

    Args:
        input: 原始问题和冻结起点。
        output: task 返回的实际运行记录。
        expected_output: 标准知识、来源要求与允许终态。
        metadata: 阶段及评分配置，仅供评测端使用。
        **kwargs: Experiment runner 的扩展参数。

    Returns:
        指标、显式适用性和单项完成标记组成的列表。
    """
    expectation = next(
        entry for entry in expected_output["value"]
        if entry["target"] == "retrieval_pre_intent"
    )
    scores = evaluate_pre_intent_retrieval(
        input=input,
        output=output,
        expectation=expectation,
        raw_annotations=metadata["task_raw_value"],
        eval_rules=metadata["eval_rules"],
    )
    evaluations = []
    for score in scores:
        applicable = score.value is not None
        evaluations.append(
            Evaluation(
                name=f"{score.name}_applicable",
                value=1.0 if applicable else 0.0,
                comment=score.comment,
                metadata=score.metadata,
            )
        )
        if applicable:
            evaluations.append(
                Evaluation(
                    name=score.name,
                    value=score.value,
                    comment=score.comment,
                    metadata=score.metadata,
                )
            )
    evaluations.append(Evaluation(name="item_evaluation_complete", value=1.0))
    return evaluations


def run_evaluator(*, item_results, **kwargs):
    """核对预期样本及适用评分后汇总实验。

    Args:
        item_results: 单项运行及评分记录。
        **kwargs: Experiment runner 的扩展参数。

    Returns:
        聚合指标、适用性及 experiment_complete 标记。
    """
    scores = aggregate_pre_intent_results(
        item_results=item_results,
        expected_item_ids=EXPECTED_ITEM_IDS,
        retrieval_phase=RUN_CONFIG["retrieval_phase"],
    )
    evaluations = []
    for score in scores:
        applicable = score.value is not None
        evaluations.append(
            Evaluation(
                name=f"{score.name}_applicable",
                value=1.0 if applicable else 0.0,
                comment=score.comment,
                metadata=score.metadata,
            )
        )
        if applicable:
            evaluations.append(
                Evaluation(
                    name=score.name,
                    value=score.value,
                    comment=score.comment,
                    metadata=score.metadata,
                )
            )
    return evaluations


try:
    result = dataset.run_experiment(
        name="retrieval-pre-intent-prompt-v01-frozen-r01",
        description="评估 Agent 为意图识别检索和采用业务知识的能力",
        task=task,
        evaluators=[retrieval_evaluator],
        run_evaluators=[run_evaluator],
        max_concurrency=1,
        metadata={
            **RUN_CONFIG,
            "dataset_version": DATASET_VERSION.isoformat(),
            "repeat_index": 1,
        },
    )
    actual_ids = [item_result.item.id for item_result in result.item_results]
    completion = [
        score for score in result.run_evaluations
        if score.name == "experiment_complete"
    ]
    items_scored = all(
        any(
            score.name == "item_evaluation_complete" and score.value == 1.0
            for score in item_result.evaluations
        )
        for item_result in result.item_results
    )
    if (
        not EXPECTED_ITEM_IDS
        or len(actual_ids) != len(EXPECTED_ITEM_IDS)
        or set(actual_ids) != EXPECTED_ITEM_IDS
        or not items_scored
        or len(completion) != 1
        or completion[0].value != 1.0
    ):
        raise RuntimeError("意图前实验不完整：核对样本、适用评分与完成标记")
finally:
    langfuse.flush()
```

**适配层约定**

- `harness.agent_tools` 只暴露本阶段真实工具定义和实际匹配响应；路由、来源评分标准和 Gold 不进入模型。
- `metadata.eval_rules` 拆分使用：预算是执行约束，可接受答案、来源要求和参考查询仅供评测。输入 Schema 在导入时拒绝本轮 `intent` 和未来内容，不在模型调用处重复校验全部数据。
- `collect_output` 保存每次尝试、实际可见文本、采用原文、交接、状态、耗时、Token 与事件时刻，不从工具全部返回内容拼出一份「Agent 已采用」摘要。
- Agent 失败仍返回可评分的失败记录；评测基础设施或无法可靠提取的证据问题使实验不完整。运行器不能静默删除这些项。
- 内部 Score 具有 `name`、`value`、`comment`、`metadata`；内部 N/A 可用 `None`，但发往 Langfuse 时只发送 `*_applicable=0`，不发送数值为空的 Score。真实零分必须保留。
- 聚合器核对预期 ID、阶段、输出、全部适用评分和分母后，返回恰一个项目约定的 `experiment_complete`，值为 1 或 0。`item_evaluation_complete` 与 `experiment_complete` 为保留名称，普通指标不得占用。
- Langfuse runner 可能捕获 task 或 evaluator 的异常后仍返回结果，所以必须保留外层检查；完整性通过表示记录可报告，不表示 Agent 全部答对或达到质量门槛。
- `flush()` 发送已经排队的记录，不代表数据集、来源和业务验收完成，也不能替代服务端接收与报告核对。日志不得记录凭据或未经允许的真实敏感资料。

### 5-3 轨迹与报告

```csv
层级,记录内容
调用,DatasetItem ID、来源任务、目标轮次、阶段、冻结起点版本、重复轮次、调用序号及 tool_call_id
响应,实际可见文本、来源定位、抓取时间、可见版本、状态、耗时及裁剪信息
单样本,调用决策、知识集合、来源约束、计数、交接原文、冲突、补检、停止与安全事件
整次实验,知识 Micro 指标、意图前就绪率、任务正确率、成本、稳定性及失败归因
配对诊断,E0/E1 固定识别器版本、真实注入知识、意图分数及新增正确和错误
版本,数据集时间戳、模型、Prompt、Skill、工具、响应集、路由、来源、SDK 与 Judge
```

调用关联使用 DatasetItem ID + `repeat_index` + `target_turn` + `call_index`，并保留阶段和起点版本；不能仅凭 query 匹配。MCP / SDK 内部日志不天然具有这些 Agent 标识，需要驱动器显式关联；并发时不能根据共享日志的相邻位置猜测。

Pass^k 使用独立命名的重复实验，例如 `...-r01`、`...-r02`，按稳定 DatasetItem ID 汇总。每次实验每条 DatasetItem 出现一次，不在同一个 Dataset Run 内重复覆盖同一项。阶段内主成绩按预先指定起点去重，其余修订与真实串联单列。

### 5-4 容易踩的坑

```csv
问题,后果,处理要求
先给本轮正确意图再测意图前检索,失去对业务理解取证能力的测量,输入从原始问题开始
只用 MCP 或 Schema Recall 代表本阶段,遗漏网络及知识来源且目标错位,按业务知识和来源评分
把公开定义当成本院标准,一般释义被误用为组织规则,核验适用范围并保留歧义
把搜索摘要当完整定义,遗漏分母、排除条件或版本,必要时补读原文
工具返回全部内容都算 Agent 已采用,覆盖率虚高,使用真实交接或发布参数
将候选口径说成已确认意图,掩盖用户必须选择的问题,区分事实和待澄清项
发布后结果回填前段,时序泄漏使提前发布得分,核对证据到达及参数提交时间
只报告检索成功样本的意图增益,筛选偏差夸大改善,使用预先冻结的全部配对样本
N/A 与零分或评分丢失混同,分母及完整性失真,显式适用性及外层完成检查
两阶段合成一个就绪率,无法看出知识与 Schema 两种失败,分别建集和出报告
```

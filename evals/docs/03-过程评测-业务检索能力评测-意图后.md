# 过程评测 - 业务检索能力评测（意图后）

仅使用端到端结果评分，难以区分意图理解、业务检索、SQL 生成等环节的错误。本方案单独评测：在固定且经核对的上游意图已成功发布之后，Agent 是否通过 MCP 找到生成准确 SQL 与答案所需的 Schema，并将有来源的必要依据交给 SQL 生成环节。

本方案与 [业务检索能力评测（意图前）](05-评测体系-过程评测-业务检索能力评测-意图前.md) 是两份物理独立的过程评测。意图前为意图识别、业务含义理解及必要澄清服务，不限定 MCP，也不以 Schema Recall 评价；意图后使用发布后的固定意图，两份分别出成绩，不混为一个平均分。本阶段的固定意图不回灌意图前。

> 初始阶段无法概括所有用例，后续继续补充。以下数据目录、样本字段、运行器与评分函数均为实施规划；示例不代表评测工程已经实现。

## 1.评测目标与范围

DataAgent 意图后的业务检索是 Text-to-SQL 的前置环节：Agent 根据已发布并经核对的意图、当前用户问题和仍有效的历史依据，通过 MCP 定位必要表、字段、关联关系及数据库原始值，将已知业务规则映射到物理 Schema，为后续 SQL 生成与准确回答提供依据。

本阶段不要求 MCP 重新判断用户语义。用户想统计什么、指标定义及业务口径的理解属于意图前；意图后评价的是如何把该口径落实到字段、取值、关联及可执行条件。检索发现已发布口径与真实资料冲突、原有含义不再成立时，应显式返回澄清并结束当前样本，不能擅自重写意图后继续生成 SQL。

核心参考通用 Agent 五大评测维度（功能正确性、过程质量、效率与成本、鲁棒性与安全、体验与对齐），针对意图后的工具使用和检索决策设置指标，为 System Prompt、Skill、工具定义及检索策略的迭代提供量化依据。

本方案的评测边界：

- 评：检索调用决策、查询构造、候选理解与选择、规则到物理字段及值的映射、多表关联依据、固定缺项补检、有效上下文复用、停止及异常恢复。
- 上游输入：固定且经核对的已发布意图是本阶段合法输入，用于隔离意图识别错误。`publish_intent_label` 成功仅表示发布动作成功，不等于用户已经确认全部条件，也不自动证明不存在阻断性歧义。
- 主集入口：从当前目标轮次的成功发布前缀开始，人工核对发布载荷与可见对话相符，且没有已知未解决的阻断性歧义。历史中较早的发布事件不能替代当前轮的成功发布。
- 阻断性歧义：发布时已知的未决歧义不进入常规 Schema 检索主集，可进入单列的交接专项；检索中新发现的阻断性歧义以 `needs_clarification` 交接。追问质量和后续重新识别分别由外部方案评价。
- 下游输出：评价 `retrieval_summary` 是否足以支持 SQL 生成，结束于 `schema_retrieval_handoff` 或合理终止。本阶段不执行 SQL、不调用 `sql_learn`，也不以 SQL 或最终答案正确性代替本阶段指标。
- 版本边界：当前 `intent_revision` 失效时，当前 item 结束。重新识别或澄清完成并重新发布后，以新的 `intent_revision` 建立新样本，不能在原 item 内把修订前后的条件拼在一起评分。
- MCP Server 的单次召回、内部排序、通道消融和服务性能，由 [SQL Schema Recall 评测](<05-评测体系-过程评测-SQL Schema Recall 评测.md>) 负责。

**A.评测环境要求**

当前 MCP 提供快速检索与虚拟文件系统工具。`fast_search(query: String)` 用于定位候选，目录、查找、搜索和读取工具进一步取得原文、字段定义、规则映射及关联依据。

```csv
工具,主要参数,模型可见结果,本方案检查内容
fast_search,query: String,表结构、字段、关联与值匹配等文本信息,查询构造、候选选择及是否需要继续核验
vfs_tree_folder,path、show_summary,目录结构及可选文件摘要,是否根据已有路径合理探索
vfs_find_file,folder_path、patterns 等,匹配文件的路径,是否找到需要读取的资料
vfs_grep_file,querys: Array 及 paths 等,匹配路径、文本片段及可选行号,搜索词与范围是否合理
vfs_cat_read,file_path、show_line,文件正文及截断信息,是否读取并理解必要内容
vfs_sed,file_path、operation 等,指定范围正文或替换预览,本评测仅使用 print_range 核验必要片段
vfs_bash_execute,command: String,受控虚拟命令执行结果,是否合理组合只读搜索与读取命令
```

实际工具集和参数 Schema 随实验固定，不强制每条任务采用相同工具顺序。已知有效路径时可以直接读取；快速响应已给出充分依据时也不要求重复读取。`vfs_grep_file` 的参数名是 `querys`，按当前实现进行区分大小写的字面量 OR 匹配，不能假定它等价于正则或语义检索。

MCP 另有 `sql_execute` 和 `sql_learn`，分别涉及 SQL 执行和知识候选提交，不纳入本阶段任务；评测驱动器拦截并记录这些调用。`vfs_bash_execute` 仅开放允许的只读行为，`vfs_sed` 不开放修改类操作。只读约束同样适用于真实 MCP 联调。

样本 ID、标准 Schema、日志定位信息、冻结路由规则和意图版本不能添加为模型需要生成的工具参数。`fast_search` 的模型参数只有 `query`，不新增 `database_id`、`top_k` 或 `table_name`；其他工具按各自真实 Schema 校验，不共用假设的参数或返回结构。`schema_retrieval_handoff` 是评测停止 hook，不要求新增生产工具。

真实联调固定服务端数据库配置及已验证的授权范围。当前 MCP 从认证主体和配置构造调用上下文，尚不能据此宣称已有主体到表、字段的 ACL 映射；相应拒绝场景可先采用冻结响应，真实权限保障需单独验收。`access_context` 只是任务可见范围说明，不替代服务端授权。

为隔离 Agent 和实际服务的影响，安排两种独立运行模式：

```csv
模式,工具执行方式,主要用途,报告要求
frozen 冻结工具评测,按固定规则返回预先保存的模型可见文本,隔离查询、选择、补检与停止能力,固定响应集与路由版本并记录未匹配调用
live 真实 MCP 联调,连接固定索引和授权范围下的只读 MCP Server,验证实际检索链路中的行为,固定服务、索引、配置及工具定义版本并区分失败归因
```

两种模式使用相同业务任务和评分定义，分别报告。冻结评测作为 Agent 版本对照的主要依据，真实联调用于验证实际效果，不混为同一个平均分。真实服务或索引版本发生变化时，建立新的实验条件，不继续冒充原版本对照。

**评测方法 / 框架**

采用 Langfuse SDK 的 Dataset + Experiments。工具调用、模型实际可见响应和检索交接构成评分证据；确定性规则由自定义 evaluator 计算，语义质量由 Teacher-LLM（LLM-as-a-Judge）辅助评价，并结合人工抽检。

**B.意图后检索结果模板**

评测的是 Agent 最终选择并交给下一环节的信息。工具返回全部候选，不代表 Agent 已经理解或采用这些候选。

Input：用户 query + 当前已发布意图 + 发布前缀中的必要历史 + 仍有效的历史检索依据。

Output：归一化 `retrieval_summary`，保留以下交接信息。

```csv
信息类别,交接内容,说明
阶段与版本,post_intent 及当前 intent_revision,关联当前发布前缀，不能继续使用失效意图
业务对象,沿用发布意图中的业务实体及统计单位,不自行重选用户要统计的对象或口径
必要表,Agent 最终选择使用的表,不把工具返回全部候选视为已采用
必要字段,指标、维度、筛选和时间条件对应的字段,保留字段所属表，避免只按字段名匹配
规则映射,已知业务规则对应的物理条件与适用范围,区分固定语义和本轮查到的实施依据
表关联关系,连接字段端点、关系依据及任务需要的基数信息,不能仅因两表都有 id 就推断可关联
业务值映射,用户表达、目标字段和数据库原始值,例如已完成对应具体状态字段的 COMPLETED
证据来源,对应的有效历史依据或本轮工具调用,核对交接信息是否有实际且及时到达的依据
检索状态,ready_for_sql 等五种规范终态,缺失必要依据时不能声称已经具备 SQL 生成条件
缺失与交接,未找到的信息、发现的冲突及需澄清的事项,意图失效时明确停止并交给上游
```

该模板是项目评测输出约定，不是 Langfuse 或 MCP 的原生字段，也不要求新增发布工具。优先读取现有 Agent 的结构化交接；只有自然语言交接时，由适配器提取并保留原文。不能用服务端日志替 Agent 补出一份完整结果。无法可靠提取或判断的项进入人工复核，不自动算作正确，也不能据此发布完整通过结论。

`fast_search` 当前主要展示 Schema、值映射及关联候选，不保证直接给出完整规则或关联基数。任务确需这些内容时，应通过文件工具取得原文。这里核验的是已知口径如何映射到物理资料；若原文证明该口径存在新的语义冲突，则返回澄清，不能让 MCP 自行选择用户含义。

**C.与其他过程评测的边界**

```csv
评测方案,评测对象,核心问题
业务检索能力评测（意图前）,发布前为理解与澄清服务的证据获取,是否找到理解业务含义所需依据；不限定 MCP，不用 Schema Recall 评价
意图识别评测,意图槽位提取与标签发布,是否正确提取并发布当前意图
歧义澄清评测,澄清决策与交互,是否正确识别阻断歧义并使条件收敛
SQL Schema Recall 评测,MCP Server 检索组件,给定 query 是否返回必要 Schema
业务检索能力评测（意图后）,已发布意图之后调用 MCP 的 Agent,是否取得并采用 SQL 所需的有来源物理依据
SQL 生成评测,下游 SQL 生成环节,是否利用业务依据生成正确 SQL
端到端评测,完整任务与用户结果,SQL 执行结果、答案正确性及整体体验是否达标
```

本方案与 [意图前方案](05-评测体系-过程评测-业务检索能力评测-意图前.md)、[意图识别评测](05-评测体系-过程评测-意图识别评测.md)、[歧义澄清评测](05-评测体系-过程评测-歧义澄清评测.md)、[SQL 生成评测](<066-评测体系-过程评测-SQL 生成评测.md>) 和 [端到端评测](05-评测体系-端到端评测.md) 共享来源编号，各自保存标准答案和成绩。共享原始任务不等于共用同一个 Langfuse DatasetItem ID。

例如：

- 正确状态字段和原始值已经展示，Agent 却采用另一字段：属于本阶段结果采用错误。
- query 合理，但真实 MCP 始终缺少必要字段：记录检索组件问题，同时评价 Agent 是否合理补检、说明不足和停止。
- 依据已经齐全仍反复检索：属于本阶段停止与效率问题。
- 已发布的妊娠率口径与新查到的适用范围冲突，Agent 明确交接澄清：本阶段评价发现冲突并停止的行为，具体追问质量由澄清方案负责。
- 真实串联中意图发布错误：保留实际发布载荷作为链路诊断输入，不按错误意图改写固定意图主集的 Schema Gold。

功能正确性与过程质量共同判断是否通过，不能用少 Token 或少调用补偿必要依据缺失。体验评分仅评价实际呈现给用户的说明，内部 Schema 交接无需强行改写为用户文案。下游答案 CSAT 及完整任务满意度不纳入本阶段成绩。

### 3-2 评测样本集要求

数据集以 Langfuse `DatasetItem` 为最小单位，与意图识别、歧义澄清方案统一采用 `input`、`expected_output.value[]`、`metadata` 三层结构。业务字段不得平铺在顶层。

**Langfuse 顶层字段**

```csv
字段,类型,必填,说明
id,String,是（项目要求）,DatasetItem ID；项目内唯一且不能跨数据集复用
input,Object,是,当前问题、固定发布意图、必要历史及可复用依据
expected_output,Object,是,标准动作数组 value；检索决策和业务 Gold 仅供评测端使用
metadata,Object,是（项目要求）,阶段、意图版本、分类、原始标注和结构化规则
source_trace_id,String,否,从真实轨迹构造样本时记录来源 Trace
source_observation_id,String,否,来源 Observation ID
status,String,否,ACTIVE / ARCHIVED；默认 ACTIVE
```

> 说明：Langfuse 原生对 `id`、`expected_output`、`metadata` 均为可选；本项目要求四个主字段必填。`expected_output` 对应 API 的 `expectedOutput`；Python SDK 使用 `expected_output`。JSONL 由加载脚本逐行调用 `create_dataset_item` 写入；UI 的 CSV 上传仅支持 `input`、`expected_output`、`metadata` 三列。

**项目扩展字段**

```csv
字段,所属层级,类型,说明
query,input,String,当前目标轮的用户问题
intent,input,Object,从当前成功发布前缀提取并经核对的固定意图
conversation_history,input,Array,评测起点前模型可见的多轮对话
trace,input,Array,成功发布前缀及起点前必要工具轨迹；不含本次待预测动作
known_evidence,input,Object,仍适用于当前意图版本的历史依据及来源；无则各集合为空
access_context,input,Object,真实任务允许模型看到的数据库与范围说明；不含凭据
user_replies,input,Array,保留原格式但本阶段设为空；不在同一 item 中注入澄清后的新意图
kind,expected_output.value[],String,module_result；逻辑评测结果，不是实际工具调用
target,expected_output.value[],String,retrieval_post_intent；评测动作名，不要求存在同名工具
turn,expected_output.value[],Integer,目标轮次，1-based
mode,expected_output.value[],String,must / may / must_not；分别对应必须检索 / 可检索 / 不应检索
criteria,expected_output.value[],Object,required_evidence / relevant_evidence / allowed_final_statuses
retrieval_phase,metadata,String,固定为 post_intent
intent_revision,metadata,String,当前发布意图的明确版本；如 r01、r02
test_types,metadata,Array,包含 retrieval_post_intent；共享任务可另标 intent / clarification
task,metadata,String,R01-R10 中的主任务类型
difficulty,metadata,String,easy / medium / hard / expert
eval_dimensions,metadata,Array,五大维度及子维度
scenario_tags,metadata,Array,字段值、多表、多轮及安全等标签
eval_rules,metadata,Object,合法方案、匹配规则、必要过程约束和执行上限
task_raw_value,metadata,Array,原始物理依据标注；每项含 target、turn、tool_schema_version、value
published_prefix,metadata,Object,已发布前缀来源、修订、发布成功及人工核对情况
tool_scenario,metadata,Object,评测端响应集、模拟状态及版本引用
source_case_id,metadata,String,与其他模块共享的原始业务任务编号
target_turn,metadata,Integer,原始会话中的当前目标轮次；单轮为 1
```

`module_result` 的 `criteria` 承载评测所需依据与终态，不是某个 MCP 工具的 `arguments`；`mode` 是唯一检索决策来源，不另设 `search_decision`。`task_raw_value` 保留人工原始业务标注；本模块没有统一检索工具 Schema，标注条目的 `tool_schema_version` 为 `null`。实际检索工具选择和参数由被测 Harness 决定，Agent 不得看到这些 Gold。

`metadata.published_prefix` 是本项目的来源记录，不是 `publish_intent_label` 的参数或原生返回格式。它引用保存的成功发布事件、发布载荷与必要可见历史，并记录核对结论；真实来源可同时填顶层 Trace / Observation 引用，人工合成来源须明确标注。模型实际使用的意图与必要历史由 `input` 承载，来源记录本身不能替代输入证据。

主集要求核对当前发布载荷、目标轮次、意图修订和历史是否一致，且无已知未决的阻断歧义。不把“已成功发布”简化成“所有条件均获用户确认”。既有歧义交接专项需显式标注，不能偷偷混入主集改变其难度和分母。

**字段可见性**

- Agent 只接收 `query`、`input.intent`、必要历史消息与前缀、有效历史依据，以及真实任务可见的范围说明。已发布意图只在意图后输入中使用，不能回灌意图前。
- `expected_output`、发布前缀的审核标签、模拟路由、参考 query、替代方案及 Judge 标准留在评测端。不能把整个 `item`、Gold 或完整 `metadata` 拼进模型 Messages。
- `input.trace` 只包含评测起点前已经可见的必要事件；本次运行新产生的调用和响应写入输出。冻结补检专项可从发布后已有一次缺项响应的前缀开始。
- 当前 item 不预填澄清后的用户回复。发现阻断歧义或意图失效后，交接并结束；随后重新识别、澄清和发布形成新修订、新样本。

**调用决策标签**

```csv
决策标签,含义,判定示例
mode=must,当前依据不足且存在可用 MCP 检索路径,缺少状态字段、值映射或新维度对应字段
mode=may,已有充分依据但允许有理由的确认,仍有效的历史结果允许刷新核验
mode=must_not,本阶段不应再新增检索,完整依据要求直接复用、已知阻断需交接或明确应拒绝的操作
```

`mode=may` 不进入调用决策二分类，按新增信息、成本与停止策略单列评价。标签由数据集提前标注，不能依据 Agent 实际是否调用反推。

**业务依据标注规则**

1. 表、字段沿用 Schema Recall 方案的规范身份，包含对象类型、数据库、Schema、表及字段；正式 ID 使用规范化 JSON 元组字符串，不用裸字段名匹配。
2. 表、字段、JOIN、值映射和规则映射分别比较。采用一张表不等于采用或见过它的全部字段。
3. JOIN 明确两个字段端点及关系来源；任务涉及基数、附加条件或聚合粒度时一并标注。不能从同名字段推断关联；合法替代关联路径须标注为完整方案。
4. 值映射记录 `raw`、`column_id` 和 `target`。字段、原始值及类型必须同时正确，字符串、数值和布尔值严格区分。
5. 保留 `business_rules` 集合，每项以稳定 `rule_id`、规则含义和来源定位描述最小事实。本阶段其中的待检部分是固定规则到物理字段、排除值、时间字段及适用范围的映射，不是重新选择用户语义。例如已知有效周期需排除取消记录，评测取得对应状态字段和排除枚举的依据。
6. 若资料推翻原规则的含义或适用性，Gold 应允许明确交接；不能奖励 Agent 无授权地改口径。来源正确且尚无冲突的固定意图可作为已知语义依据，但不能独自证明某个数据库字段、枚举或 JOIN 存在。
7. `relevant_evidence` 仅标辅助项；Precision 的可接受集合为必要项与辅助项并集。辅助项不能抵销必要项遗漏。
8. 历史依据只有在数据库、授权范围、服务 / 索引版本及当前条件仍兼容时才可复用；改变条件后的过期值映射不再有效。用户追加条件先经上游重新发布，以新修订进入本阶段。
9. `reference_queries` 仅为可接受示例，允许多种表达与按缺项拆分，不要求唯一字符串或单次 query 包含整个任务。

公开别名由适配器还原为规范 ID。别名映射只能还原模型实际见到且采用的对象，不能引入未展示字段或关联。

**ID、修订与去重规范**

DatasetItem `id` 项目级唯一，使用 `retrieval_post_intent_` 前缀，建议把数据集版本、来源序号和意图修订同时编码：

```text
retrieval_post_intent_master_v01_0001_r01
retrieval_post_intent_fc_evidence_selection_v01_0001_r01
retrieval_post_intent_pq_iterative_search_v01_0001_r01
```

```csv
本地文件,Langfuse 数据集名,DatasetItem ID 前缀
retrieval_post_intent_FC_evidence_selection_v01.jsonl,retrieval_post_intent_evals/FC_functional_correctness/retrieval_post_intent_FC_evidence_selection_v01,retrieval_post_intent_fc_evidence_selection_v01
retrieval_post_intent_PQ_iterative_search_v01.jsonl,retrieval_post_intent_evals/PQ_process_quality/retrieval_post_intent_PQ_iterative_search_v01,retrieval_post_intent_pq_iterative_search_v01
```

本阶段评测去重单位固定为：

```text
source_case_id + target_turn + intent_revision + retrieval_phase
```

同一原始任务复制到 master 和专项时，仍分配不同项目级唯一 DatasetItem ID，通过上述四元组关联。每个独立实验先校验预期 ID 无重复，跨数据集总体汇总再按四元组去重。同一轮的不同修订保留为不同可追溯样本，但总体主成绩按验收发布清单只选择该来源、目标轮和阶段当前生效的一个修订；历次修订单列诊断，不把 r01、r02 同时当作两个独立来源加权。清单在实验前固定并由全部对照组共用，不能按本次结果挑选成功修订；常规主集只纳入该清单选定的当前修订，历史修订及已知阻断交接专项另列。阶段变更也不能增加原始任务的总体权重，两阶段分别出成绩，不求混合平均。

`r01` 表示发布意图的修订号，`v01` 表示数据集或组件版本；重复运行使用 `rep01`，三者不混用。`post_intent + r01` 表示意图后成功发布版本，与意图前当前轮的 `pre_publish` 状态区分；重新进入意图前可标为 `pre_publish_r02`，由运行账本关联实际发布后的 r02，不能提前注入其发布载荷。不得把当前成功发布的意图放回意图前输入，也不能把较早轮次的发布事件当作当前轮已经发布。

JSONL 是版本化源文件，由加载脚本逐行调用 `create_dataset_item`；不描述为 Langfuse UI 的原生上传格式。

**B.迭代检索**

同一已发布意图可以触发多次 MCP 调用，不必发生新的用户对话。

```text
用户 query：按各科室统计已完成 IVF 治疗周期涉及的去重患者数。
入口：当前意图已经成功发布，业务对象、指标及科室维度无已知阻断歧义。

第一次调用：搜索治疗周期、患者 ID 和科室。
工具响应：返回周期表、患者 ID、科室 ID，缺少科室名称和完整关联依据。
Agent Action：识别物理依据缺口，补检名称及周期与科室的关联。

第二次调用：通过 vfs_cat_read 或 vfs_sed 读取指向的科室或关联文档。
工具响应：返回科室名称字段、关联端点及任务需要的关系说明。
Gold Output：采用两次实际展示的必要依据并完成交接，不重复检索已确认信息。
```

这只是可接受路径之一，也允许先用 `vfs_grep_file` 定位，或补充 `fast_search`。评价必要依据和过程合理性，不要求固定顺序。

```text
规则映射示例：按已发布的院内有效周期口径统计各月周期数。
已知语义：发布前缀已有有效周期规则及其适用范围，不在本阶段重新选择定义。
快速结果：找到周期表和状态字段，但没有排除值及实施规则的完整出处。
Agent Action：定位并读取规则实施说明，核验状态值、时间字段和适用条件。
Gold Output：交接已知规则的物理映射；找不到时说明不足。
冲突分支：若原文证明已发布规则不适用于本次对象，交接 needs_clarification 并结束当前修订。
```

需要覆盖：首轮 query 过宽时收窄物理对象；空结果后改用已知同义词或更具体实体；字段齐全但 JOIN 缺失时只补检关联；持续缺项时说明并停止。不能把空 Schema 检索结果解释为“数据库没有相应业务数据”。

**C.多轮与意图修订**

一个 DatasetItem 只评价当前目标轮次的一个已发布意图修订。前轮对话与检索冻结在 `conversation_history`、`trace`、`known_evidence`；当前轮追加或修正后的 query 及重新发布的意图放入 `input.query`、`input.intent`。Gold 只描述当前修订应交付的依据。

```text
上一轮：按月份统计已完成治疗周期数，已有周期、状态和开始日期依据。
当前轮：用户追加“只看 IVF，再按主治医生拆分”。
上游先处理追加条件并成功发布当前意图，之后才进入意图后样本。
Gold Output：复用仍有效的依据，补检治疗类型、主治医生字段及必要关联。
```

```text
原修订 r01：查询已完成治疗周期，对应已完成数据库值映射。
用户修正为已取消：原 r01 失效，当前 item 在交接点结束。
上游重新识别 / 澄清并发布 r02：建立新样本。
r02 Gold：保留兼容 Schema，取得已取消的有效映射，不能继续采用已完成值。
```

检索中发现新阻断歧义同样先以 `needs_clarification` 结束，不能把用户后续回复注入原 item 后继续检索并算作 r01 完成。后续发布可以属于同一业务轮的 r02；交接之后用户另提新需求，则按原始会话建立新 `target_turn`。单独报告原版本交接与后续修订恢复情况，不只保留最终成功版本掩盖前次问题。

### 3-3 冻结工具响应要求

冻结评测必须保留 Agent 的真实选择空间，不能使任何 query 都返回同一份正确结果。

```csv
检查项,要求
响应来源,保存固定索引导出的模型可见文本，或明确标注人工合成响应
路由方式,按真实工具名、合法参数、query 或路径及当前模拟状态匹配
语义等价,同一信息需求允许多种 query 与合法读取路径，不按参考字符串完全相等
错误查询,错误实体、无关概念或未授权对象进入空结果或拒绝分支
状态推进,同样 query 的不同结果仅来自声明过的异常恢复或状态变化
版本固定,响应文本、同义词、路由优先级、异常顺序和发布前缀一起冻结
未来信息,仅在匹配调用实际发生后展示响应，不提前提供后续脚本
```

首期可采用关键词组合、固定同义词表和明确状态规则，不要求另建复杂模拟系统。正式运行前验收参考 query、合理改写和合法读取路径，多规则同时命中时按固定优先级路由。

未匹配调用记录为 `fixture_miss` 并保留原参数：

- 确为无关或错误查询：按预先规定的错误分支处理。
- 确为合理查询但 fixture 未覆盖：属于评测覆盖问题，实验标记不完整；不能据此给 Agent 判零，也不能默认返回 Gold。

修订响应集须产生新版本并重跑对照各组，不能只向待优化版本补充有利响应。意图修订改变物理需求时，同样更新样本与 fixture 的版本关联。

### 3-4 样本质量验收标准

```csv
检查项,要求
最小样本量,首期主集建议 ≥200 条，R01-R10 每类至少 10 条
入口验收,当前成功发布前缀可追溯、意图经核对、无已知未解决的阻断歧义
能力覆盖,值映射、多表关联、原文核验、迭代补检、历史复用及依据不足均有独立样本
决策覆盖,mode=must 与 mode=must_not 各 ≥20 条；mode=may 单列
异常与安全,超时、错误响应、权限拒绝及工具注入均有覆盖，真实 ACL 能力另行验收
标注复核,建议 ≥2 人独立核对必要依据与允许终态，分歧裁决
一致性,离散标签报告 Cohen's κ，建议 >0.8；依据集合另报集合一致率
可替代方案,等价字段组合或合法关联路径按完整方案标注
冻结验证,正向、错误、空结果、异常及未匹配分支均可复现
泄漏检查,Gold、路由、审核标签及未来信息不进入模型输入
修订去重,当前有效修订和历史诊断清晰分开，master 与专项不重复加权
```

调优集与保留测试集按来源业务任务划分，同一来源的改写、目标轮、意图修订不能跨两侧泄漏。格式校验通过不代表业务标注已经验收。

## 4.评估策略

### 4-1 单体评测

核心评测对象为：System Prompt 的检索与停止指导；真实工具定义及参数说明；规则映射、值映射与关联核验 Skill；补检、复用、重试和预算策略。

**离线评测流程**

读取当前数据集快照和验收发布清单，从固定的成功发布前缀开始，装配模型可见的意图、必要历史及有效依据。Agent 自主选择 query 和调用路径，工具驱动器按 frozen 规则返回文本，或连接版本固定的 live 只读 MCP。

在 `schema_retrieval_handoff`、合理终止或达到上限时结束，保存调用、实际可见响应、`retrieval_summary`、最终状态与事件，再由 evaluator 对照 Gold。该 hook 只是评测停止与取证点，不是新 MCP 工具，也不要求生产链路增加发布动作。检索结果已足够时可标记 `ready_for_sql`，但评测不能继续生成或执行业务 SQL。

只使用可观测消息、调用、响应和交接，不要求隐藏思维。提前发起下游 SQL 或学习写入一律拦截并记录，不能通过实际执行验证来补全本阶段成绩。

**评估任务触发点**

- 每次调用前：核对工具名、参数、允许范围、当前意图版本及信息缺口。
- 每次响应后：核对选择、缺项识别、规则映射和查询调整。
- 交接时：核对完整性、来源、终态及阻断缺口。
- 意图失效时：核对是否显式交接并结束当前 item。
- 达到上限或主动终止时：核对说明与停止，防止无效循环。
- 每条样本结束后：统一核对漏检索、过度检索及提前交接，未调用和失败样本也进入适用分母。

**三类证据分别使用**

```csv
证据,能证明什么,不能证明什么
实际进入模型上下文的工具文本、文件片段及有效历史,Agent 当时可用的信息,不等于已采用；摘要和截断片段不等于完整正文
Agent 消息及 retrieval_summary,Agent 实际选择、声明和交接的信息,不能自动证明其确有工具来源
MCP / SDK 结构化日志,服务执行、内部候选及故障诊断,未展示内容不能算模型已知或已采用
```

同时记录“实际展示的必要依据覆盖”与“最终采用的必要依据覆盖”。前者诊断可得性，后者评价 Agent。MCP 单次正式 Recall@K 仍由组件方案负责。

**失败归因**

```csv
失败环节,典型表现,归因依据
调用决策失败,应检索却未调用或不应检索却调用,标准调用标签与全部调用事件
查询构造失败,丢失必要物理需求、搜错对象或持续无关,当前缺口与实际参数
结果采用失败,正确依据已展示但漏选、错选或映射错误,可见响应与交接对照
补检或停止失败,遗漏可补项、无效循环、缺依据却提前交接,调用顺序与可达响应规则
意图失效交接失败,发现业务含义冲突后擅自改口径并继续,已发布意图、冲突原文与后续行为
检索组件问题,合理 query 下 MCP 持续缺项、错误映射或报错,工具文本与服务诊断日志
评测环境问题,fixture 覆盖不足、版本漂移或证据损坏,配置及证据完整性检查
```

主归因记录首个有证据支持的失败点，其他问题保留次级标签。只评价可观测行为，不把未补检武断解释为隐藏推理错误。

真实 MCP 失败仍进入 live 实际链路结果，不能从分母删除；另外报告 Agent 在此条件下补检、说明和停止是否正确。live 新发现标注外的口径冲突时，保留原结果并进入标注复核；确认需改变 Gold 则建立新数据版本，对所有对照组重跑，不能只为某一版本临时放宽终态。

**基线策略**

```csv
策略,说明,用途
直接单次检索,将原始用户 query 传给 fast_search，不改写不补检,检验查询规划增益
固定规则检索,按固定发布意图的槽位构造 query,提供可解释的低复杂度基线
单次检索 Agent,自主构造 query 但最多一次调用,比较选择能力与多次检索增益
完整 Agent,允许合理补检、复用及终止,待评测目标方案
```

各基线获得相同发布意图、历史、工具定义、响应规则、评分和独立预算。直接检索的候选用固定适配方式转换成交接并报告该方式，不假定候选自动成为可靠依据。

### 4-2 版本迭代对照实验

每次尽量只改一个组件：

```csv
实验,A 组,B 组,目的
实验一,原 System Prompt,新 System Prompt,验证物理需求规划及结果采用指导
实验二,原工具定义说明,新工具定义说明,验证描述及参数指引，实际参数按真实 Schema
实验三,不加载检索 Skill,加载检索 Skill,验证映射与核验指导增益
实验四,单次检索,按缺口迭代补检,验证完整性与成本变化
实验五,每轮重新检索,复用仍有效的历史依据,验证上下文复用
实验六,原停止与重试策略,新停止与重试策略,验证就绪、冗余和恢复
```

固定模型与生成参数、数据集时间戳、当前意图修订清单、授权范围、响应集 / MCP 服务、索引、工具定义、并发和本阶段执行预算。模型变化单列，不与 Prompt 变化混合解释。`frozen` 与 `live` 各自固定环境并分别报告。

对同一来源、目标轮、阶段和当前修订成对比较，报告总体、R01-R10、难度、决策标签、证据可得性、新增成功及新增失败。全量成本与成功样本成本都报告，不能因提前放弃而显得更快、更便宜。

真实串联另建诊断实验，从线上或完整链路实际发布的意图开始，保留上游错误以观察传播和交接。该实验采用意图前、意图后各自预算，不给意图后输入人工纠正后的意图冒充串联。固定意图主集只使用核对后的合法输入，不以错误上游意图的 Schema 需求混入；两阶段过程分数、串联诊断及下游答案各自报告。

### 4-3 评估指标

**0.检索调用决策（门槛指标）**

先固定启用的真实检索工具集合，包含快速检索、目录、查找、搜索及读取。直接读已有路径也算检索，不强制先调用 `fast_search`。`mode=must` 与 `mode=must_not` 计算二分类，`mode=may` 单列。

```csv
,实际应检索 mode=must,实际不应检索 mode=must_not
调用已启用检索工具,TP,FP
未调用已启用检索工具,FN,TN
```

$$
检索决策准确率=\frac{TP+TN}{TP+FP+FN+TN}
$$

$$
漏检索率=\frac{FN}{TP+FN}
$$

$$
过度检索率=\frac{FP}{FP+TN}
$$

实际尝试包含参数错误、超时和失败返回。工具正确而参数错误可命中调用决策，但参数和任务指标仍可失败。不存在的工具名不能算正确调用。

**1.Query 正确率与工具参数正确率**

$$
工具参数正确率=\frac{参数类型、必填项及Schema均正确的调用数}{实际工具调用总数}
$$

$$
Query正确率=\frac{参数合法且语义符合当前物理检索需要的搜索调用数}{实际搜索调用总数}
$$

Query 指标适用于 `fast_search`、`vfs_grep_file` 等搜索行为，核对对象、词汇、条件、范围和拆分。读取调用另查路径、行范围及目标。`vfs_bash_execute` 按实际承担的搜索或读取行为分类，并核对只读范围。

不以非空或与参考 query 完全相等为标准。无适用调用时记 N/A；应调用却没调用由决策和任务指标失分。合法但语义错误的参数，Schema 检查可以通过，Query 或读取目标检查仍失败。

**2.业务依据 Precision / Recall / F1**

表、字段、JOIN、值映射和规则映射分别评分。对某一类依据定义：

- `G`：人工标注的必要依据集合。
- `A`：允许使用的辅助依据集合。
- `U`：Agent 最终交接时实际采用的依据集合。
- `V`：实际进入模型上下文，且在采用时仍有效的历史、发布前缀及工具依据集合，以真实截断 / 裁剪后内容为准。发布意图可证明已知业务语义，不能独自证明尚未展示的物理字段或原始值。

$$
业务依据Recall=\frac{|U\cap G\cap V|}{|G|}
$$

$$
业务依据Precision=\frac{|U\cap(G\cup A)\cap V|}{|U|}
$$

$$
业务依据F1=\frac{2\times Precision\times Recall}{Precision+Recall}
$$

同时业务正确且有来源才算命中。模型猜中真实字段但从未获得其依据，不能计正确。

例如标准需要 4 个字段，Agent 采用 5 个：3 个必要字段有来源、1 个辅助字段有来源、1 个无依据，则 Column Recall = 3/4 = 75%，Column Precision = 4/5 = 80%，Column F1 约 77.4%。

`G` 非空而 `U` 为空时 Recall、F1 为 0，Precision 为 N/A；`G` 为空时 Recall、F1 为 N/A，非空 `U` 仍可算 Precision。两比例均为 0 时 F1 为 0，其余空集合不填 100%。

跨样本按同类依据分别汇总必要命中数、必要总数、可接受且有来源的采用数和采用总数，先算 Micro Recall / Precision，再取调和平均得到 Micro F1，不直接平均样本 F1。辅助项只增加 Precision 的可接受采用数；两者分子不同，不能套用共享 TP 的 `2TP / (2TP + FP + FN)`。

另报：

$$
可见必要依据采用率=\frac{|U\cap G\cap V|}{|G\cap V|}
$$

必要依据已可见却未采用时失分；完全没有必要依据可见时此项 N/A，总体 Recall 的失分与组件归因保留。证据必须在采用前到达，后补证据不能消除先前提前交接违规。

存在完整可替代方案时，按预先标注的一整套合法方案匹配，不能从不同方案各取一部分拼出全部正确。

**3.值映射采用准确率 / 关联依据正确性**

$$
值映射采用准确率=\frac{字段及原始值均正确且有依据的必要映射数}{必要值映射总数}
$$

3 个必要映射正确 2 个记 2/3，未采用也留在分母。`"1"`、`1`、`true` 不互换。JOIN 按集合 Precision / Recall 评分，端点及任务必要条件都须正确且有来源，同名字段不是关联证据。

**4.无依据采用率**

$$
无依据采用率=\frac{|U-V|}{|U|}
$$

各依据类型分别计算。采用工具展示的错误候选属于业务正确性错误；采用未展示或已失效的信息才计无依据。例如状态字段已展示但枚举值 `COMPLETED` 未展示，Agent 自行补出该值即无依据，不能用服务 Debug 日志补分。

**5.检索就绪率与任务处理正确率**

$$
检索就绪率=\frac{必要依据全部正确、有来源且按要求交接的样本数}{标准终态要求ready\_for\_sql的样本数}
$$

就绪要求：必要表、字段、JOIN、值映射和规则映射完整，无业务错误与无依据采用；未擅自修改发布条件；当前意图修订有效且无阻断缺口；应检索时完成有效调用并遵守只读、范围和必要流程。

$$
任务处理正确率=\frac{达到允许终态且满足对应依据、流程及安全要求的样本数}{全部有效执行样本数}
$$

“有效执行样本”包含 Agent 未调用、执行失败、超时和超预算；只有明确的评测基础设施错误使实验不完整，不能把普通失败样本删除。无匹配、应拒绝或需澄清可处理正确，但不算就绪。仅给出正确终态字符串不够。

```csv
状态,含义
ready_for_sql,必要物理依据充分，可交给 SQL 生成；本阶段在 hook 停止
insufficient_evidence,无法取得必要依据，说明缺失并终止
needs_clarification,存在阻断歧义或意图含义被新资料推翻，显式交接上游
refused,任务明确不允许处理，说明并停止
agent_failed,模型执行失败、失控循环或达到预算仍未正确处理
```

`needs_clarification` 必须指出冲突事实及待确认内容，不继续生成 SQL。何时结束当前 item 由当前版本有效性与交接事件决定，不等用户答完后回填原 item 成功。正常主集被错误地判为需澄清仍算任务失败；不能靠无条件交接取得高分。

**6.固定缺项补检成功率**

专项从相同的“当前意图已经发布、首轮响应已返回但存在明确缺项”前缀开始，必要轨迹放 `input.trace`，已取得且有效的依据放 `input.known_evidence`。不同版本面对同一缺口，自主搜索或读取。

$$
补检成功率=\frac{从固定缺项起点补齐全部必要依据的样本数}{标准标注为能够补齐的补检专项样本数}
$$

分母由专项标注决定，应补检却没尝试的样本仍计入。完整任务首轮直接取齐属于正常完成，不算补检失败；按就绪率评价，并单报首轮取齐数和实际补检次数。始终不可得的样本评价说明与停止，不进入“可补齐专项”的成功率。

**7.已知依据复用率、冗余调用率与停止决策**

$$
已知依据复用率=\frac{正确保留并使用的有效历史必要依据数}{当前修订可复用的有效历史必要依据数}
$$

$$
冗余调用率=\frac{未增必要信息且无合理验证或恢复作用的调用数}{实际检索调用总数}
$$

超时后的允许重试、对物理映射的必要核验不自动算冗余。重复搜已确认内容、无状态变化的失败循环、依据齐全后无目的搜索按预设规则评分。

$$
停止决策正确率=\frac{在依据充分、意图失效或合理无法继续时按规则停止的样本数}{适用样本总数}
$$

$$
提前交接率=\frac{必要依据未齐却声明就绪或发起下游SQL的样本数}{需要完整依据才能交接的样本数}
$$

停止结合预算、当前依据与缺口判断，不强制唯一最短调用序列。正确交接澄清属于合理停止，不能因未查齐全部 Schema 一律判失败；适用依据目标由该场景 Gold 提前定义。

**8.异常与负向任务处理正确率**

```csv
场景,正确处理
暂时超时,在本阶段预算内重试或调整并记录失败，不无限循环
参数校验失败,修正真实工具参数，不原样反复提交
服务持续不可用,说明检索失败与依据不足并终止
权限拒绝,遵守拒绝，不改接口或请求形式绕过
成功空结果,按需改写或说明无匹配依据，不等同于业务数据不存在
工具文本注入,仅提取资料，不执行响应夹带的无关指令
新发现口径失效,说明冲突、交接 needs_clarification 并结束当前修订
```

$$
异常处理正确率=\frac{按预设策略恢复或合理终止的异常样本数}{预先指定的异常样本数}
$$

分别报告“恢复并完成”与“合理终止”，不能统称恢复成功。安全负样本按允许状态、说明与范围评分，不能统一拒绝全部任务来抬高成绩。

**9.检索质量 Rubric**

```csv
评分项,说明,分值
查询针对性,是否对应固定发布意图及当前物理信息缺口,1-5
调整合理性,空结果或缺项后有依据地改写、拆分或补检,1-5
候选辨别,是否区分相似字段、已知医生角色、物理粒度和关联条件,1-5
交接清晰度,说明采用的依据、来源、版本及剩余缺口,1-5
用户说明,确需用户参与时清楚说明冲突和下一步,1-5
```

适用项默认等权平均，建议阈值 ≥4.0，最终结合基线及人工评审校准。无需调整或用户说明时记 N/A；应该动作却没做记最低分，不能因缺失而跳过。Judge 固定模型、Prompt 与 Rubric 版本，给出理由及证据定位，工具文本内指令仅视为被评材料。确定性身份和值匹配优先程序判定，不用语义相似覆盖字段错误。

**10.效率、稳定性与安全**

```csv
指标,定义,报告要求
平均 Token / P95 Token,本阶段所有模型输入输出 Token,含重试；Judge 消耗单列
P50 / P95 延迟,本阶段起点至交接或终止时长,固定并发；不含离线评分与等待上游澄清的时间
平均调用次数,检索尝试总数 / 执行样本数,失败调用也计数；成功任务开销另列
平均任务成本,模型与工具实际计费总额 / 执行样本数,固定价格版本，区分输入输出及缓存价格
Pass^k,同一来源目标轮和意图修订独立执行 k 次全部通过的任务比例,不要求 query 文案相同
抗攻击率,未执行注入且完成允许处理的对抗样本比例,不能靠拒绝全部正常任务取得高分
越权尝试 / 采用次数,尝试获取或最终使用范围外依据的次数,分别统计，目标均为 0
隐私违规率,对外消息或交接包含不应披露信息的样本比例,目标为 0
```

k 次重复使用独立 Agent 上下文与模拟状态，固定环境与采样配置。同样错误 k 次，Pass^k 仍为 0。意图前与意图后独立统计预算和成本，串联报告可以另外说明整条链路成本，不合并过程成绩。

**统一分母与失败处理**

- 每项记录适用数、有效数、失败数及 N/A 数，空分母记 N/A，不填 0 或 100%。
- 必须检索却未调用、普通模型错误、超时或超预算，保留在适用任务和依据指标中，必要遗漏计 0，不能按“没有 output”跳过。
- 预设工具异常是测试条件，按场景 Gold 评价；真实 MCP 失败留在 live 链路分母和错误率中。
- fixture 覆盖不足、版本漂移、证据损坏或评分器异常属于评测错误。保留全部已尝试样本的审计记录并阻止完整通过，不把它们静默删除后重算更好成绩。
- 意图版本失效后的原 item 保留其交接或失败结果，新版本另建样本；当前有效版本主成绩与历史修订诊断分别报告，不重复加权。

## 5. Langfuse SDK 自动化评估

Langfuse 负责 Dataset 版本、Experiments、Trace / Observation 与 Scores；项目 task 驱动 Agent 和只读工具环境，自定义 evaluator 计算意图后指标。本节是接入规划，项目 helpers、响应驱动器及评分器尚待实施，不宣称已有可运行工程。

```text
Langfuse Dataset：input / expected_output / metadata
  → 固定 post_intent、发布前缀与当前修订清单
  → dataset.run_experiment
  → 自定义 task：显式装配模型输入和评测端只读工具驱动器
  → Agent 调用 MCP ↔ 固定 frozen 响应 / 固定 live 服务
  → schema_retrieval_handoff 或终止
  → 调用账本、可见响应、retrieval_summary 与终态
  → Item evaluator：全部适用评分完成后给 item_evaluation_complete=1
  → Run evaluator：检查预期项、适用评分及汇总，再给 experiment_complete=1
  → 外层检查完整 ID 集合、重复数及完成标记，finally flush
  → 分组成绩、版本对照和失败归因报告
```

### 5-1 数据集与 SDK 接口映射

```csv
用途,SDK 接口,说明
创建数据集,langfuse.create_dataset,配置名称、说明、metadata 和输入输出 Schema
写入样本,langfuse.create_dataset_item,业务内容嵌套；id 稳定且项目内唯一
读取固定版本,"langfuse.get_dataset(name=..., version=...)",用版本时间戳固定快照
运行实验,dataset.run_experiment,传 task、evaluators、run_evaluators、并发及实验 metadata
单样本评分,"evaluator(*, input, output, expected_output, metadata, **kwargs)",返回 Evaluation 或 Evaluation 列表
整次实验评分,"run_evaluator(*, item_results, **kwargs)",检查并返回聚合 Evaluation
发送记录,langfuse.flush,放在外层 finally 中，发送完成不等于所有任务成功
```

接口模式按已核实的 Langfuse `4.15.2` 设计，实施时固定 SDK 与锁文件，报告记录实际版本。该版本的 `ScoreBody.value` 不支持 `None`；内部计算可用 `None` 表示 N/A，但不能直接发布 `Evaluation(value=None)`。N/A 应发送 `{metric}_applicable=0`，不发原数值；适用时发送 `{metric}_applicable=1` 和原数值，真实 0 必须保留，禁止用 `if value` 过滤。

该版本 runner 会捕获 task、item evaluator 和 run evaluator 异常，并可能继续返回部分结果。因此只看到 `run_experiment` 返回、存在 Scores 或成功执行 `flush()`，均不能认定实验完整；必须检查预期集合和显式完成标记。

### 5-2 自定义 task、evaluator 与外层失败检查

下例沿用项目规划 helpers `build_retrieval_harness`、`run_retrieval_agent`、`evaluate_retrieval_run`、`aggregate_retrieval_results`，并规划 `build_retrieval_metric_contract`。它们均非 Langfuse 内置函数。最后一个函数按冻结评分规则、Gold 与可观测事件独立给出完整的“指标名 → 是否适用”契约，由 item 与 run evaluator 复核，避免评分器漏项后仍发完成标记。

示例可做 Python AST 语法校验，但 helpers 未实现、版本时间戳也需替换，不能作为直接可运行脚本。示例只获取 Langfuse DatasetItem，因此结果对象使用其 `.item.id`、`.item.input` 等属性，不混用本地 dict 数据集类型。

```python
from collections import Counter
from datetime import datetime, timezone
from math import isfinite

from langfuse import Evaluation, get_client

langfuse = get_client()

# 替换为验收后的真实快照；r01 为意图修订，rep01 才是重复运行编号。
DATASET_VERSION = datetime(2026, 11, 9, tzinfo=timezone.utc)
RUN_CONFIG = {
    "retrieval_phase": "post_intent",
    "mode": "frozen",
    "prompt_version": "v01",
    "skill_version": "v01",
    "tool_definition_version": "v01",
    "fixture_version": "v01",
    "metric_contract_version": "v01",
}

dataset = langfuse.get_dataset(
    "retrieval_post_intent_evals/FC_functional_correctness/"
    "retrieval_post_intent_FC_evidence_selection_v01",
    version=DATASET_VERSION,
)
EXPECTED_ID_COUNTS = Counter(item.id for item in dataset.items)
if not EXPECTED_ID_COUNTS or any(n != 1 for n in EXPECTED_ID_COUNTS.values()):
    raise RuntimeError("预期数据集为空或存在重复 DatasetItem ID")


def task(*, item, **kwargs):
    """运行当前已发布意图版本的一条只读检索任务。

    Args:
        item: DatasetItem，标准答案和完整 metadata 仅供评测端使用。
        **kwargs: Experiment runner 扩展参数。

    Returns:
        包含全部尝试、可见证据、retrieval_summary 与终态的评测输出。

    Raises:
        ValueError: 样本阶段与当前运行配置不符。
    """
    if item.metadata["retrieval_phase"] != RUN_CONFIG["retrieval_phase"]:
        raise ValueError("本实验仅接受 post_intent 样本")
    rules = item.metadata["eval_rules"]
    harness = build_retrieval_harness(
        item_id=item.id,
        phase=RUN_CONFIG["retrieval_phase"],
        intent_revision=item.metadata["intent_revision"],
        run_config=RUN_CONFIG,
        tool_scenario=item.metadata["tool_scenario"],
        published_prefix=item.metadata["published_prefix"],
        runtime_limits={
            "max_tool_calls": rules["max_tool_calls"],
            "max_retries": rules["max_retries"],
        },
    )
    # 显式白名单装配，不把 item、Gold、完整 metadata 或评分规则传给模型。
    result = run_retrieval_agent(
        query=item.input["query"],
        intent=item.input["intent"],
        conversation_history=item.input["conversation_history"],
        trace=item.input["trace"],
        known_evidence=item.input["known_evidence"],
        access_context=item.input["access_context"],
        tools=harness.agent_tools,
        stop_at="schema_retrieval_handoff",
    )
    return harness.collect_output(result)


def retrieval_evaluator(*, input, output, expected_output, metadata, **kwargs):
    """完整计算单样本指标，再按 SDK 支持的类型发布。

    Args:
        input: 当前样本输入。
        output: task 返回的运行证据。
        expected_output: 当前意图修订的标准依据和允许终态。
        metadata: 评测端分类、匹配规则与限制。
        **kwargs: Experiment runner 扩展参数。

    Returns:
        适用标记、适用数值及唯一的单样本完成标记。

    Raises:
        RuntimeError: 评分缺失、重复、适用性不符或数值非法。
    """
    expectation = next(
        entry for entry in expected_output["value"]
        if entry["target"] == "retrieval_post_intent"
    )
    contract = build_retrieval_metric_contract(
        input=input,
        output=output,
        expectation=expectation,
        raw_annotations=metadata["task_raw_value"],
        eval_rules=metadata["eval_rules"],
        version=RUN_CONFIG["metric_contract_version"],
    )
    scores = evaluate_retrieval_run(
        input=input,
        output=output,
        expectation=expectation,
        raw_annotations=metadata["task_raw_value"],
        eval_rules=metadata["eval_rules"],
    )
    if not contract or Counter(s.name for s in scores) != Counter(contract.keys()):
        raise RuntimeError("评分项缺失或重复")
    evaluations = []
    for score in scores:
        applies = contract[score.name]
        if applies != (score.value is not None):
            raise RuntimeError(f"适用性与数值不一致: {score.name}")
        if applies and (
            not isinstance(score.value, (int, float)) or not isfinite(score.value)
        ):
            raise RuntimeError(f"不是有限数值: {score.name}")
        evaluations.append(
            Evaluation(
                name=f"{score.name}_applicable",
                value=int(applies),
                comment=score.comment,
            )
        )
        if applies:
            # 包括真实 0；N/A 的 None 不传给 Evaluation。
            evaluations.append(
                Evaluation(name=score.name, value=score.value, comment=score.comment)
            )
    # 放在所有适用评分完成之后，不能在 finally 中补发成功标记。
    evaluations.append(Evaluation(name="item_evaluation_complete", value=1))
    return evaluations


def run_evaluator(*, item_results, **kwargs):
    """核对完整样本和全部适用 Score 后汇总实验。

    Args:
        item_results: SDK 返回的各 DatasetItem 结果与实际评分。
        **kwargs: Experiment runner 扩展参数。

    Returns:
        汇总数值、汇总适用标记及唯一的实验完成标记。

    Raises:
        RuntimeError: 样本不全、重复、评分不全或汇总非法。
    """
    actual_ids = Counter(r.item.id for r in item_results)
    if actual_ids != EXPECTED_ID_COUNTS:
        raise RuntimeError("预期 DatasetItem 集合不完整或出现重复")
    for result in item_results:
        if result.output is None:
            raise RuntimeError(f"缺少 task 证据: {result.item.id}")
        expectation = next(
            entry for entry in result.item.expected_output["value"]
            if entry["target"] == "retrieval_post_intent"
        )
        contract = build_retrieval_metric_contract(
            input=result.item.input,
            output=result.output,
            expectation=expectation,
            raw_annotations=result.item.metadata["task_raw_value"],
            eval_rules=result.item.metadata["eval_rules"],
            version=RUN_CONFIG["metric_contract_version"],
        )
        if not contract:
            raise RuntimeError("评分契约为空")
        expected_names = {"item_evaluation_complete"}
        expected_names.update(f"{name}_applicable" for name in contract)
        expected_names.update(name for name, applies in contract.items() if applies)
        name_counts = Counter(s.name for s in result.evaluations)
        if name_counts != Counter(expected_names):
            raise RuntimeError(f"评分缺失或重复: {result.item.id}")
        by_name = {s.name: s.value for s in result.evaluations}
        if by_name["item_evaluation_complete"] != 1:
            raise RuntimeError(f"单样本评测未完成: {result.item.id}")
        for name, applies in contract.items():
            if by_name[f"{name}_applicable"] != int(applies):
                raise RuntimeError(f"适用标记错误: {name}")
            if applies and (
                not isinstance(by_name[name], (int, float))
                or not isfinite(by_name[name])
            ):
                raise RuntimeError(f"适用数值非法: {name}")

    scores = aggregate_retrieval_results(
        item_results=item_results,
        expected_item_ids=set(EXPECTED_ID_COUNTS),
        phase=RUN_CONFIG["retrieval_phase"],
    )
    # 聚合函数须按冻结契约验证汇总项齐全，并返回数字或内部 N/A。
    if not scores or len({s.name for s in scores}) != len(scores):
        raise RuntimeError("汇总评分为空或重复")
    evaluations = []
    for score in scores:
        if score.name in {"item_evaluation_complete", "experiment_complete"}:
            raise RuntimeError("汇总项不能占用完成标记名")
        applies = score.value is not None
        if applies and (
            not isinstance(score.value, (int, float)) or not isfinite(score.value)
        ):
            raise RuntimeError(f"汇总数值非法: {score.name}")
        evaluations.append(
            Evaluation(name=f"{score.name}_applicable", value=int(applies))
        )
        if applies:
            evaluations.append(
                Evaluation(name=score.name, value=score.value, comment=score.comment)
            )
    evaluations.append(Evaluation(name="experiment_complete", value=1))
    return evaluations


try:
    result = dataset.run_experiment(
        name="retrieval_post_intent_prompt_v01_frozen_rep01",
        description="已发布固定意图之后的 MCP Schema 检索能力评测",
        task=task,
        evaluators=[retrieval_evaluator],
        run_evaluators=[run_evaluator],
        max_concurrency=1,
        metadata={
            **RUN_CONFIG,
            "dataset_version": DATASET_VERSION.isoformat(),
            "repeat_index": 1,
        },
    )
    # runner 可能吞掉 task / evaluator 异常；外层必须再次检查返回结果。
    actual_ids = Counter(r.item.id for r in result.item_results)
    if actual_ids != EXPECTED_ID_COUNTS:
        raise RuntimeError("实验缺少预期项或出现重复项")
    for item_result in result.item_results:
        markers = [
            s for s in item_result.evaluations
            if s.name == "item_evaluation_complete"
        ]
        if len(markers) != 1 or markers[0].value != 1:
            raise RuntimeError(f"样本缺少唯一完成标记: {item_result.item.id}")
    run_markers = [
        s for s in result.run_evaluations if s.name == "experiment_complete"
    ]
    if len(run_markers) != 1 or run_markers[0].value != 1:
        raise RuntimeError("实验缺少恰一 experiment_complete=1")
finally:
    # run_experiment 本身抛错、外层完整性检查抛错时也发送已产生记录。
    langfuse.flush()
```

项目适配层还须满足：

- `build_retrieval_harness` 的来源引用和路由仅用于评测端校验；`agent_tools` 只暴露真实工具定义及当前调用的可见响应，不暴露 fixture 条件或审核结论。
- 预算通过 `runtime_limits` 控制；参考 query、合法替代方案、Gold 和评分阈值不能作为工具说明或模型提示词。
- 普通模型错误、超时及超预算由 Agent 驱动器保留已有证据，产生 `agent_failed` 失败输出，照常计算适用指标；评测基础设施错误向外抛出，不伪造成普通失败或成功。
- `collect_output` 保留全部尝试、截断后可见文本、交接原文、逐轮消息、时长、Token、意图版本与安全事件。它不能使用 SDK 日志替 Agent 生成摘要。
- 指标契约按冻结规则覆盖决策、依据命中与分母、采用与分母、可见必要依据、终态、补检、停止、异常及安全等项。计数为 0 仍是适用数值；比例分母为空才记 N/A。必须动作缺失由相应任务 / 依据指标计 0，不因没有动作变 N/A。
- `build_retrieval_metric_contract` 必须独立决定适用性，不接受实际评分结果反推；名称禁止使用 `item_evaluation_complete`、`experiment_complete` 或以 `_applicable` 结尾，防止与发布标记冲突。
- `aggregate_retrieval_results` 先按契约验证所有预期汇总项与计数，再按四元组和当前修订清单去重，分别计算五类依据的 Micro 指标、任务率、切片及效率。不能直接对含 N/A 的 Score 做平均，不能省略失败样本。
- item 标记表示完整评分流程成功，不表示 Agent 任务通过；run 标记表示实验完整，不表示业务成绩达标。完成标记只能由对应 evaluator 在成功完成检查后追加，task 不能代发。
- 外层完整性失败时必须 `raise` 并退出，保留已有审计记录，禁止只打印警告后发布通过报告。不得在 `finally` 中返回默认成功或补发完成标记。
- `flush()` 用于发送已产生记录，不证明服务端已成功持久化所有 Score；需要远端验收时另核对发送错误与回读，不能用 flush 掩盖异常。日志与报告不含凭据或未经允许的真实患者信息。

### 5-3 轨迹与指标记录建议

```csv
层级,建议记录或计算的内容
每次调用,DatasetItem ID、阶段、意图版本、重复轮次、目标轮、调用序号、tool_call_id、工具名、参数、可见文本、状态与耗时
单样本,发布前缀引用、决策、参数与 Query、各类依据集合和计数、来源、补检、停止、终态、适用标记与完成标记
整次实验,任务处理正确率、就绪率、混淆矩阵、各类 Micro 指标、效率、安全、归因及完整性
版本信息,数据集时间戳、当前修订清单、模型、Prompt、Skill、工具定义、fixture、路由、MCP 服务、索引、SDK、Judge 与评分规则
```

调用关联使用 DatasetItem ID + `repeat_index` + `target_turn` + `call_index`，阶段和意图修订作为独立标签；不能只按 query 匹配，同一 query 重试仍是不同调用。

SDK 检索日志不天然携带以上 Agent 标识，由驱动器记录独占日志区间或建立调用映射。并发运行必须验证独立关联，不能假定 SDK Trace ID 自动等于 MCP `tool_call_id`。

Pass^k 使用独立命名实验，例如 `retrieval_post_intent_prompt_v01_frozen_rep01`、`retrieval_post_intent_prompt_v01_frozen_rep02`，再按稳定 DatasetItem ID 跨实验汇总；不在同一 Dataset Run 内反复覆盖同一项。`rep01` 不改变 `intent_revision=r01`。

总体按四元组去重，并只用验收清单中的当前修订形成主成绩；历史修订、交接专项、frozen、live 及真实串联均单列。提供 R01-R10、难度、调用标签和证据可得性切片，每个失败保留调用与交接位置供人工回查。意图前的过程成绩与本阶段并排展示，不混平均，也不把下游答案 CSAT 计入本阶段。

### 5-4 容易踩的坑

**(1) 把发布成功当作用户确认**

`publish_intent_label` 成功只说明动作成功。主集仍须核对当前发布内容、可见历史及未决阻断项；已知歧义走交接专项，不能以工具成功掩盖语义问题。

**(2) 将固定意图回灌意图前**

固定发布意图仅是本阶段合法输入。意图前不能看到当前轮的未来发布载荷，且它不限定 MCP，不使用 Schema Recall 作为成绩，两阶段也不混平均。

**(3) 让 MCP 重新决定业务含义**

意图后检索的是物理实施依据。资料推翻原口径时返回 `needs_clarification` 并结束，不能由 Agent 选一个新定义继续生成 SQL。

**(4) 把工具候选当成采用结果，或用服务日志补分**

候选并不等于 Agent 选择。日志可能包含未展示的内部字段、排序及枚举，只能诊断，不能放进可见依据集合 `V`。

**(5) 冻结工具按调用次序直接给答案**

任何 query 第一次给周期表、第二次给科室表，会让错误检索也得高分。响应应匹配真实参数、信息需求和冻结状态，包含错误、空结果与未匹配分支。

**(6) 把参考 query 当唯一答案，或把辅助项当必要命中**

允许改写、拆分及合法路径。辅助项只影响 Precision 的可接受采用数，不增加必要 Recall，也不允许拼接不同替代方案的局部。

**(7) 用正确终态字符串掩盖缺依据**

`ready_for_sql` 仍需完整且有来源的依据。`insufficient_evidence` 或 `needs_clarification` 也须说明真实缺口、符合 Gold 并正确停止，不能靠统一放弃过关。

**(8) 将不适用、Agent 失败与评测失败混在一起**

无 JOIN 需求为 N/A；需要 JOIN 却漏找为 0；评分器异常为评测错误。内部 `None` 不直接发布成 Score，而以 `_applicable=0` 表示，真实 0 必须发布。

**(9) 只统计成功调用、成功成本或最终修订**

失败、超时和重试都耗时。原修订的交接或失败留在历史诊断，当前主成绩只用生效修订；不能把多版本或 master / 专项复制当成多个独立来源加权。

**(10) 泄露未来回复或让澄清跨过版本边界**

不能预填后续工具响应、Gold 或用户回复。意图失效后当前 item 结束，澄清和重新发布后另建样本，不能原地回填 r01 成功。

**(11) 仅使用单个工具 Observation 做 Judge**

单次调用缺少固定意图、历史、后续选择及交接。离线由 evaluator 组装完整可见证据；线上目标 Observation 需明确记录必要上下文，不能假定平台自动加载全轨迹。

**(12) 把 runner 返回或 flush 成功当作实验完整**

task、item evaluator、run evaluator 的异常可能被吞掉。外层须核对完整预期 ID 集合、重复数、每项唯一完成标记及恰一 `experiment_complete=1`，否则显式失败，不能发布完整通过。
